# Память Scott

Scott хранит факты о пользователе и историю завершённых разговоров.
Они сохраняются между запусками и используются в чате и голосовом режиме.

## Факты

Явно сказанные сведения могут сохраняться автоматически:

- «Меня зовут Алексей».
- «Я живу в Казани».
- «Мой проект Орбита написан на C++ и Qt».
- «Предпочитаю короткие ответы».

Команда «запомни, что …» и ручное добавление во вкладке «Память» остаются.
Вопросы, примеры, цитаты, код и строки с очевидными паролями/API Token
не считаются автоматическими фактами. Ответы модели тоже не становятся
фактами о пользователе. Автоматический разбор пока распознаёт ограниченный
набор явных формулировок; остальные сведения можно сохранить вручную.

Новые имя, сведения о том же проекте и предпочтения по длине ответа
обновляют соответствующую запись. Во вкладке «Память» автоматические записи
отмечены «Из диалога». Переключатель **«Запоминать факты»** отключает
автоматическое добавление; ручное сохранение и история разговоров продолжают
работать.

Список вмещает 200 коротких фактов по 200 символов. При заполнении
автоматические записи вытесняются раньше ручных. Основные сведения об имени,
месте проживания и стиле ответа имеют приоритет среди автоматических записей.
Для запроса модель получает подходящие по теме факты, включая старые,
в пределах 2500 символов.

На вопросы «Как меня зовут?» и «Где я живу?» Scott может ответить из
сохранённых явных сведений без обращения к модели.

## История разговоров

Завершённые пары «пользователь → ответ» сохраняются в постоянном архиве.
Размер короткого контекста модели больше не ограничивает историю на диске.
Неудачный запрос к модели без ответа не создаёт незавершённую пару.
Локальные ответы и голосовые команды тоже попадают в историю.

В запрос включаются последние сообщения и найденные фрагменты прошлых
разговоров. Поиск объединяет совпадения слов и поиск по смыслу через локальную
многоязычную модель E5. Например, вопрос об оформлении окна может найти
обсуждение дизайна лаунчера без общих слов. Ключи облачных API для поиска
не нужны; история обрабатывается на компьютере.
Для «продолжим проект …» сначала подбираются разговоры по указанной теме,
включая записи старше последних 40 ответов. Если тема не названа,
используется недавняя история.

При первом запуске в фоне скачивается открытая квантованная модель
`intfloat/multilingual-e5-small` (около 129 МиБ вместе с токенизатором).
Она работает на CPU через ONNX Runtime, использует два потока и не занимает
видеопамять Whisper или Silero. Пока загрузка/индексация не закончилась,
либо если модель недоступна, работает поиск по словам. Поиск по смыслу
также помогает выбирать старые факты по теме вопроса.

Векторы разговоров сохраняются в той же SQLite-базе и используются после
перезапуска. Для индекса длинная реплика разбивается на фрагменты; учитываются
первые 6000 символов каждой стороны разговора, по 128 токенов на фрагмент.
Полный текст сохраняется в архиве, прежний индекс слов остаётся доступным.
Векторы фактов кэшируются в оперативной памяти. Уточнение или удаление факта
сбрасывает этот кэш; удалённые факты фильтруются и из смысловых результатов.
«Очистить историю» удаляет разговоры и их векторы одной транзакцией.

Для отключения модели есть `SCOTT_SEMANTIC_MEMORY=0`. `GET /memories`
возвращает `semantic_search`: состояние (`not_loaded`, `loading`, `indexing`, `ready`,
`unavailable`, `disabled`), устройство, модель и число проиндексированных
разговоров. Ошибка смыслового индекса не мешает обычной памяти.

Поиск вероятностный: широкие и неоднозначные формулировки могут выбрать
соседнюю тему. Проверенные результаты и пропуски:
[отчёт смыслового поиска](backend-semantic-2026-10-06.md).

Последние 20 сообщений хранятся в коротком рабочем контексте. При отправке
предыдущие сообщения ограничены примерно 6000 символами с учётом текущего
вопроса, фрагменты архива — 2000 символами. Длинные прошлые сообщения
сокращаются, полный текст остаётся на диске. Сам текущий вопрос сохраняется
целиком, поэтому очень большой ввод может превышать этот бюджет.

В новом чате Qt есть отдельные именованные диалоги и вложения. Его контекст
включает до десяти завершённых пар с бюджетом около 32 000 символов текста;
дополнительно подбираются записи общего архива. История на диске сохраняется
полностью. Очистка конкретного диалога удаляет связанные записи архива и файлы.
[Подробнее о чате](chat.md).

Старые `backend/data/conversations.jsonl` и `data/memory.jsonl` подхватываются
при запуске. Исходные файлы при первом переносе сохраняются. Историю, которую
прежняя версия уже обрезала и которой больше нет в этих файлах, восстановить
невозможно.

## Просмотр и очистка

Во вкладке «Память» доступны поиск, категории, удаление факта, переключатель
автозапоминания и число ответов в истории.

Удалённые факты исключаются из подбора соответствующих исходных реплик
в контекст. Сами диалоги хранятся отдельно. **«Очистить историю»** удаляет
постоянный архив и короткую историю; сохранённые факты остаются.
Файлы прежних версий, использованные для переноса, отдельно не удаляются.

## Файлы и API

- `backend/data/memories.json` — факты, источник и время уточнения.
- `backend/data/memories.settings.json` — автозапоминание и отметки для
  исключения удалённых фактов из старого контекста.
- `backend/data/conversations.sqlite3` — постоянная история и индекс поиска.
- `backend/data/conversations.jsonl` — последние сообщения и запасной источник
  при недоступности архива. При следующем запуске он помогает восстановить
  запись, если временно не удалось записать её в SQLite.
- `GET /memories` — факты, `auto_capture`, `archived_turns` и предупреждения.
- `POST /memories/settings` с `{"auto_capture": false}` — смена режима.
- `GET /ai/memory-stats` — статистика истории.
- `POST /ai/clear-memory` — очистка истории.

Архив использует стандартную библиотеку Python, новые зависимости не нужны.
Проверки выполняются на временных файлах и подменённых провайдерах;
личные факты и реальные API Token в тестах не используются.

Результаты проверки: [отчёт backend](backend-memory-2026-10-05.md).

## Проверка на настоящей модели

```powershell
py -3.13 backend/check_memory.py --live
```

Проверка создаёт вымышленные сведения о пользователе и проекте, проводит
18 посторонних диалогов и запускает каждый сценарий в новом процессе:
сведения о пользователе, прежнее решение по проекту, продолжение работы,
исправление имени и удаление факта. Итого — 25 запросов к выбранной модели.
Без `--live` запросы не отправляются.

Личная история, факты, проекты и настройки характера не загружаются.
Из настроек приложения читается подключение к модели. Микрофон,
воспроизведение и исполнитель команд не используются. Временная память
удаляется; вымышленные ответы и результаты остаются в `reports/`,
который исключён из Git. Сохранённые настройки модели не меняются.

Если выбранная модель OpenRouter недоступна, можно указать `--model ID`:
это временный выбор для проверки, разрешены только доступные модели
с нулевой ценой входных и выходных токенов и запроса. Для повторной проверки
того же вымышленного разговора служит `--seed-report путь/к/report.json`.

Автоматическая оценка проверяет конкретные тестовые сведения; ответы нужно
также сверять вручную. Успех этих сценариев не означает, что любое
перефразирование или любой провайдер будут работать одинаково.

Результаты настоящей модели: [отчёт проверки](backend-memory-live-2026-10-05.md).

Локальный поиск по смыслу можно проверить отдельно, без облачных моделей:

```powershell
py -3.13 backend/check_semantic_memory.py --download
```

Этот инструмент использует вымышленную историю и возвращает сравнение
поиска по словам и по смыслу. Без `--download` модель должна быть в кэше.
Код возврата 1 означает, что в проверочном корпусе остались пропуски;
подробности, включая отрицательные случаи, сохраняются в отчёте.
