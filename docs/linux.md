# Scott AI на Linux

Начиная с 2.2.0 единственный голос — Scott Voice. Его штатная установка
пока поддерживает Windows/NVIDIA CUDA; на Linux доступны чат и распознавание,
поддержка синтеза Scott Voice ещё не подтверждена. Прежние пакеты 2.1.1
сохраняют прежние голоса. Матрицы и размеры ниже относятся к указанным в них
проверенным пакетам, а не к новому варианту без Silero.

Экспериментальный Qt-пакет для Linux x86-64. Он включает приложение,
библиотеки Qt, QML-модули, backend и отдельный Python 3.13.16. Системный Python
для установки не нужен; зависимости и модели речи устанавливаются при первом
запуске. Установка, backend и запуск X11 проверены на Ubuntu 22.04/24.04,
Debian 12/13, Fedora 44 и Arch. В текущих исходниках дополнительно проверен
нативный Wayland через Weston с программным рендерингом на Debian12.
Настоящие GNOME/KDE, AMD, микрофон и звук ещё требуют проверки.
Scott Voice остаётся экспериментом Windows/NVIDIA.

## Режим распознавания

Мастер предлагает автоматический выбор ускорения или обычный CPU.
Прежние сохранённые профили распознавания поддерживаются. Чат и локальные
команды работают независимо от установки Scott Voice; для RX580 используется CPU.

## Установка

Сначала установите системные библиотеки для своего дистрибутива.

### Ubuntu 22.04/24.04 и Debian 12/13

```bash
sudo apt-get install ca-certificates fonts-dejavu-core libportaudio2 libpulse0 ffmpeg \
  libegl1 libgl1 libopengl0 libxkbcommon-x11-0 libxcb-cursor0 libxcb-icccm4 \
  libxcb-keysyms1 libxcb-image0 libxcb-render-util0 libxcb-xinerama0 libxcb-xkb1 \
  libxcb-shape0 libwayland-client0 libwayland-cursor0 libwayland-egl1
```

### Fedora 44

```bash
sudo dnf install ca-certificates dejavu-sans-fonts mesa-libEGL mesa-libGL \
  libxkbcommon-x11 xcb-util-cursor xcb-util-wm xcb-util-keysyms \
  xcb-util-image xcb-util-renderutil libXcursor libXrandr libXi libXrender \
  pulseaudio-libs portaudio ffmpeg-free
```

Для старого пакета 2.0.1 в сеансе Wayland нужен XWayland, если он ещё не установлен:

```bash
sudo dnf install xorg-x11-server-Xwayland
```

### Arch Linux

```bash
sudo pacman -Syu --needed ca-certificates ttf-dejavu mesa libglvnd \
  libxkbcommon libxkbcommon-x11 libxcb xcb-util-cursor xcb-util-wm \
  xcb-util-keysyms xcb-util-image xcb-util-renderutil libxcursor \
  libxrandr libxi libxrender libpulse portaudio ffmpeg
```

Для старого пакета 2.0.1 в сеансе Wayland, если XWayland ещё не установлен:

```bash
sudo pacman -S --needed xorg-xwayland
```

### Установка приложения

Скачайте [архив Linux x86-64](https://github.com/stalker1243/Scott-AI/releases/download/v2.2.0/ScottAI-2.2.0-Qt-linux-x86_64.tar.gz)
и [файл SHA256](https://github.com/stalker1243/Scott-AI/releases/download/v2.2.0/ScottAI-2.2.0-Qt-linux-x86_64.tar.gz.sha256).
Вход в GitHub для скачивания выпуска не нужен.

```bash
sha256sum -c ScottAI-2.2.0-Qt-linux-x86_64.tar.gz.sha256
tar -xzf ScottAI-2.2.0-Qt-linux-x86_64.tar.gz
cd ScottAI-2.2.0-Qt-linux-x86_64
./install.sh
~/.local/share/ScottAI/run.sh
```

Сама установка выполняется без sudo и создаёт ярлык в меню приложений.
Папку можно выбрать через `bash ./install.sh --prefix /путь/к/ScottAI`.
Если `./install.sh` не запускается, попробуйте `bash ./install.sh` из терминала
в распакованной папке. При ошибке `Permission denied` распакуйте архив
в домашнюю папку на разделе, где разрешён запуск программ.

В текущих исходниках после 2.0.1 установщик сохраняет журнал в
`${XDG_STATE_HOME:-~/.local/state}/ScottAI/logs/linux-install.log` и объясняет
ошибки запуска Python. Для исходной папки на `noexec` предусмотрен запасной
системный Python 3.11+ только на время копирования. Установленное приложение
по-прежнему использует Python из пакета; его контрольные суммы проверяются.
При потерянных исполняемых правах установщик восстанавливает их у известных
скриптов, лаунчера и проверенного Python. Папка назначения должна разрешать
запуск. Скрипт из текущих исходников также принимает `sh ./install.sh`,
проверяет полноту распаковки и объясняет отсутствие доступа к журналу.
Эти исправления включены в архив 2.1.0.

### AppImage в текущих исходниках

Подготовлена экспериментальная упаковка в один файл AppImage для x86-64.
В 2.1.0 AppImage доступен вместе с tar.gz-пакетом.
Системные графические и звуковые библиотеки из списка выше всё ещё нужны.
Python и Qt входят в образ, зависимости backend и модели готовятся при первом
запуске и сохраняются вне него. AppImage не уменьшает размер Torch или моделей.

После проверки SHA256 скачанного файла его можно назвать `ScottAI.AppImage`:

```bash
chmod +x ScottAI.AppImage
./ScottAI.AppImage
```

Устанавливать приложение через `install.sh` для этого формата не требуется.
Файл должен находиться на разделе, где разрешён запуск программ.
Если FUSE недоступен, используйте встроенную распаковку и запуск:

```bash
./ScottAI.AppImage --appimage-extract-and-run
```

Она требует временного места для распакованной программы. Для постоянной
распаковки, чтобы не повторять её при запуске:

```bash
./ScottAI.AppImage --appimage-extract
./squashfs-root/AppRun
```

Используется фиксированный [статически собранный runtime AppImage](https://github.com/AppImage/type2-runtime/tree/dd6cebedcbddde9c82f89b011e8e1d40b6e43868):
отдельная `libfuse2` ему не требуется. Для обычного запуска нужны доступ к FUSE
и системная утилита `fusermount3` — пакет `fuse3`:
[Debian](https://packages.debian.org/bookworm/amd64/fuse3/filelist),
[Fedora](https://packages.fedoraproject.org/pkgs/fuse3/fuse3/),
[Arch](https://archlinux.org/packages/extra/x86_64/fuse3/files/).
Распаковка работает без них.

AppImage, запущенный обычным способом или через `extract-and-run`, может
обновляться через отдельное окно: лаунчер закрывается, новый файл скачивается
и проверяется по SHA256 и версии, затем заменяет прежний образ. Приложение
открывается в прежнем режиме запуска. При отмене возвращается старая версия.
Файл должен принадлежать пользователю и находиться в доступной для записи
папке. Если его уже заменили вручную, установка останавливается.

Прежний образ сохраняется рядом в файле `.scott-previous-….AppImage`.
Это резервная копия для ручного возврата; она занимает место и автоматически
не удаляется. После проверки новой версии ненужные резервные образы можно
удалить самостоятельно. История, настройки и окружение Python остаются
в XDG-каталогах ниже; одинаковая версия Python использует готовое окружение.

Для постоянной ручной распаковки, системной установки или недоступного для
записи файла предлагается страница выпуска. Образ можно заменить вручную
после закрытия ScottAI и проверки SHA256. Временная папка распаковки никогда
не обновляется установщиком tar.gz. Эти изменения включены в 2.1.0.

### XDG-каталоги в текущих исходниках

Новая установка учитывает `XDG_DATA_HOME`: папка приложения —
`${XDG_DATA_HOME:-~/.local/share}/ScottAI`, ярлык меню —
`${XDG_DATA_HOME:-~/.local/share}/applications/com.scottai.launcher.desktop`.
Можно по-прежнему задать `--prefix`. Если стандартная старая установка уже
существует, установщик сохраняет её путь при смене `XDG_DATA_HOME`;
существующая установка в новом каталоге имеет приоритет.

Пути XDG должны быть абсолютными. Пустые и относительные значения игнорируются
согласно [XDG Base Directory Specification](https://specifications.freedesktop.org/basedir/latest/).
Ярлык корректно передаёт пути с пробелами, кавычками, `%` и кириллицей.
Чужой ярлык с другим путём запуска не перезаписывается. При удалении используется
сохранённый ярлык этой установки, даже если `XDG_DATA_HOME` изменился.
Публичная документация также копируется в установленное приложение.

Ошибки backend, технические журналы и измерения времени находятся в
`${XDG_STATE_HOME:-~/.local/state}/ScottAI/logs`. Для журналов можно задать
`SCOTT_LOG_DIR`; отдельные `EXECUTE_LOG_DIR` и `TIMING_LOG_DIR` сохраняют приоритет.
Архивы, созданные API диагностики без явно выбранного пути, сохраняются в
`${XDG_STATE_HOME:-~/.local/state}/ScottAI/reports`. Новые каталоги диагностики
создаются с доступом только владельцу; права существующих каталогов сохраняются.
Диагностика может собрать ZIP, даже когда папка программы недоступна для записи.

В текущих исходниках установленный Linux-пакет хранит рабочие файлы отдельно
от программы. В 2.1.0 используются новые пути:

| Данные | Папка по умолчанию |
| --- | --- |
| Чаты, вложения, память, проекты, протоколы, профиль браузера | `~/.local/share/scottai` |
| API Token, `.env`, настройки моделей, голоса и устройств | `~/.config/ScottAI` |
| Новые аудиофайлы, проверка обновлений, новые семантические веса | `~/.cache/ScottAI` |
| Технические журналы и архивы | `~/.local/state/ScottAI` |

Первые три пути учитывают соответственно `XDG_DATA_HOME`, `XDG_CONFIG_HOME`
и `XDG_CACHE_HOME`. Имя каталога данных `scottai` записано строчными буквами:
это отдельная папка, отличная от исторической папки программы `ScottAI`.
Настройки интерфейса Qt сохраняют прежнее имя `ScottAI/QtPrototype`.
Аватар установленного Linux-пакета находится в `scottai/qt/profile/avatar.json`
в каталоге данных. При первом запуске корректное старое фото копируется вместе
с обрезкой, оригинал остаётся. Запись атомарная, параллельный перенос защищён
блокировкой. Очистка фото сохраняется и не восстанавливает прежнее изображение.
### Постоянный Python в текущих исходниках

Новые установки создают базовый Python и окружение backend в
`${XDG_DATA_HOME:-~/.local/share}/scottai/runtimes/<SHA256 Python>/`.
В папке приложения `runtime` — ссылка на это окружение. Его путь сохраняется
при обновлении и переустановке; удаление лаунчера оставляет установленные
библиотеки. При смене `XDG_DATA_HOME` обновление использует записанный путь.
Разные версии базового Python получают отдельные папки, старые не удаляются.
Проверка свободного места учитывает диск окружения.

Python из пакета сначала копируется в постоянную папку без загрузки из сети.
Это добавляет отдельную копию базового интерпретатора, но позволяет запускать
окружение после смены пути приложения, в том числе из папки только для чтения.
Повторный запуск использует готовое окружение; неполная подготовка возобновляется
под блокировкой. Неизвестные папки и повреждённые файлы автоматически не удаляются.

Готовые окружения старых установок сохраняются по прежним путям: venv содержит
абсолютные ссылки, поэтому перенос простой сменой имени небезопасен. Готовый
Scott Voice также остаётся на месте. Для новых установленных Linux-пакетов его
будущий каталог — `scottai/components/voice-runtime`; `SCOTT_VOICE_HOME` сохраняет
приоритет. Это подготовка путей, установка Scott Voice на Linux пока недоступна.
Библиотеки и профиль браузера уже хранятся в каталоге данных пользователя.

Автономная проверка обновления, переустановки и двух путей readonly-образа:

```bash
python3 installer/linux/check_runtime.py --package installer/dist-linux-qt \
  --work /tmp/scott-runtime-check
```

Папка `--work` должна быть новой. Проверка использует вымышленные данные и
собственное хранилище. Опция `--wayland` дополнительно требует Xvfb и Weston.
Эта проверка моделирует readonly-каталоги. Настоящие AppImage проверяются
отдельно через FUSE и распаковку; подпись выпуска и запуск на физических
Fedora/Arch остаются отдельными задачами.

Перед первым запуском после обновления закройте старую версию и сохраните
резервную копию `backend/data`, `data` и собственного `.env`. ScottAI копирует
историю, вложения, настройки и другие рабочие файлы в новые каталоги,
сохраняя оригиналы. SQLite копируется через согласованный снимок с учётом WAL.
При конфликте разных файлов, изменении исходных данных или символической
ссылке перенос останавливается с объяснением; файлы не перезаписываются.
Устраните причину и повторите запуск. После обрыва перенос можно повторить.
Если исходная папка нужна для завершения переноса, не удаляйте её.

После успешного переноса используется новое хранилище. Очистка чата не
восстанавливает старую историю при следующем запуске или переустановке.
Не удаляйте служебные записи `.storage-v1.json` и `.storage-location-v1.json`.
Изменение XDG Data/Config после переноса требует отдельного согласованного
переноса каталогов; приложение объясняет несовпадение путей.
Новые каталоги создаются с правами `0700`, перенесённые файлы — `0600`.

Готовые локальные модели Whisper и семантического поиска переиспользуются
по прежним путям. Старый аудиокеш сохраняется, новые реплики создаются в
пользовательском кеше; повторная копия кеша и весов не создаётся.
Запуск из исходников и хранение данных Windows сохраняют прежний режим.

Нужны интернет и место под зависимости и модели. Python включён в пакет;
его архив закреплён по SHA256. Установка не меняет системный Python.
Источник Python — [python-build-standalone, выпуск 20261003](https://github.com/astral-sh/python-build-standalone/releases/tag/20261003).
При обновлении прежней установки окружение backend пересоздаётся на встроенном
Python; библиотеки потребуется подготовить заново. История и настройки остаются
на месте. Если создание окружения не удалось, прежнее окружение восстанавливается.
При обновлении используйте тот же путь установки: `.env`, история, вложения
и настройки моделей сохраняются. Установщик откажется писать в чужую непустую
папку или через символическую ссылку.

## Wayland, X11 и трей в текущих исходниках

`run.sh` выбирает нативный Wayland, когда доступны сокет сеанса и Wayland-плагин
из пакета. В остальных случаях используется XCB. Явный выбор сохраняет приоритет:

```bash
QT_QPA_PLATFORM=xcb ~/.local/share/ScottAI/run.sh
QT_QPA_PLATFORM=wayland ~/.local/share/ScottAI/run.sh
```

В Wayland размещением и переходами между обычным, развёрнутым и полноэкранным
окном управляет композитор. Произвольное центрирование и привязка к краям
отключены; перетаскивание и изменение размера используют системные операции.
Появление и скрытие анимируются внутри Qt Quick. Подробности ограничения —
[QWindow::startSystemMove](https://doc.qt.io/qt-6.11/qwindow.html#startSystemMove).
Настоящая матовость Glass зависит от композитора; Windows Acrylic в Linux
не используется.

Доступность трея обновляется во время работы. Если значок становится недоступен,
скрытое окно возвращается. При отсутствии трея опция «Закрывать в трей» недоступна,
а закрытие окна завершает приложение. Поддержка значка и его действий зависит от
окружения рабочего стола: [документация Qt](https://doc.qt.io/qt-6.11/qsystemtrayicon.html).

Для проверки установленного пакета из репозитория можно запустить:

```bash
python3 installer/linux/check_wayland.py --prefix ~/.local/share/ScottAI \
  --output /tmp/scott-wayland-check
```

Нужны Xvfb и Weston. Проверка использует отдельный программный сеанс с виртуальным
вводом и синтетические данные интерфейса. Она проверяет чат, копирование кода,
настройки голоса, подготовку, профиль и логи; сохраняет снимки и журналы.
Это не проверка настоящего микрофона, видеокарты или рабочего стола GNOME/KDE.
В CI она запускается после отключения SDK. Изменения включены в 2.1.0.

## Удаление

```bash
~/.local/share/ScottAI/uninstall.sh
```

По умолчанию рабочие данные сохраняются. Для удаления старых данных внутри
папки установки:

```bash
~/.local/share/ScottAI/uninstall.sh --delete-data
```

В текущих исходниках `--delete-data` удаляет данные внутри папки установки.
Отдельные XDG-хранилище, настройки, кеш и журналы пользователя сохраняются,
поскольку ими могут пользоваться несколько установок. Для полного удаления
их можно удалить вручную после резервного копирования и закрытия ScottAI.
Повторная установка использует сохранённые пользовательские данные.

## Сборка из исходников

Нужны Linux x86-64, CMake 3.24+, Ninja, GCC, Python 3.11+ и Qt 6.8+ с Qt Quick,
QuickControls2, Network, Widgets, WaylandClient и Test. Для WaylandClient нужны
системные заголовки Wayland (`libwayland-dev` в Debian/Ubuntu).
CI и текущая локальная проверка используют Qt6.11.2. Сборщик проверяет наличие
XCB/Wayland-плагинов и `launcher/qt.conf` перед созданием архива.

```bash
python3 -m venv installer/.cache/build-python
installer/.cache/build-python/bin/python -m pip install psutil==7.2.2
installer/.cache/build-python/bin/python installer/build_linux.py --qt-root /путь/к/Qt/6.11.2/gcc_64
xvfb-run -a ctest --test-dir ScottAI_qt/build-linux --output-on-failure \
  -E 'window_lifecycle|window_states|qml_screens'
python3 backend/run_tests.py
```

Результат — `installer/release/ScottAI-<версия>-Qt-linux-x86_64.tar.gz`
и файл `.sha256`. Сборщик использует CMake deployment API Qt и включает
использованные QML-модули, библиотеки и плагины. Уже существующий пакет
не перезаписывается; для повторной сборки выберите новый `--output` и сохраните
или уберите предыдущий архив.

Проверки не включают микрофон и не исполняют голосовые команды. В CI проверяются
установка, обновление, сохранение синтетических данных, удаление, переустановка
и запуск упакованного интерфейса без доступа к Qt SDK. Тесты поведения

### Сборка AppImage

После сборки чистого `installer/dist-linux-qt` установите `file` и
`desktop-file-utils`, затем выполните:

```bash
python3 installer/build_appimage.py --package installer/dist-linux-qt \
  --output installer/release/ScottAI-local-Qt-linux-x86_64.AppImage
```

Сборщик проверяет SHA256 фиксированных appimagetool 1.9.1 и runtime 20251108.
После первого скачивания `--offline` использует проверенный кеш; другой кеш
можно задать через `--tools-cache`. Сборка не требует FUSE, Qt SDK нужен только
для предыдущей сборки Qt. Существующие образы не перезаписываются. Исходники,
рабочая установка с `runtime`, личные данные и внешние ссылки отвергаются.
Временная папка сборки должна находиться на файловой системе Linux, которая
поддерживает символические ссылки и различает регистр имён.

`installer/linux/check_appimage.py` запускает два отдельно собранных образа,
проверяет замену файла, постоянный Python, синтетический SQLite-чат, вложение
и настройки. По умолчанию проверяется `extract-and-run`; `--fuse` требует
доступного `/dev/fuse`. `check_wayland.py --appimage FILE` проверяет настоящий
образ через распаковку в приватном Weston. Проверки не включают микрофон.
