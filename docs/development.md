# Разработка ScottAI

Основной интерфейс — C++/Qt Quick, backend — Python. Готовность выпуска
проверяется отдельно для исходников, установщика и настоящего голосового
разговора. Сборка и unit-тесты не заменяют проверку аудиоустройств.

## Запуск и сборка Windows

```powershell
./ScottAI_qt/build.ps1 -Test
./ScottAI_qt/run.ps1
```

Скрипт сборки проверяет Qt, MinGW и Ninja. По умолчанию используется
`ScottAI_qt/build`. Другую папку можно передать через `-BuildDirectory`.
Backend запускается фоновым процессом лаунчера.

## Backend-тесты

```powershell
py -3.13 backend/run_tests.py
py -3.13 backend/run_tests.py tests/test_release_voice.py -q
```

Runner создаёт изолированную копию публичных ресурсов и исключает реальные
настройки, ключи, историю, модели и кеши. Обычный прогон исключает integration
и slow-тесты. Аппаратные проверки требуют отдельного стенда и явной готовности
пользователя, если включаются микрофон или динамики.

## Scott Voice

Рабочие ресурсы находятся в `voice/runtime/`; синтетический принятый эталон —
в `assets/scott-voice/reference/`. Это внутренние модули worker, а не набор
пользовательских команд для запуска исследований.

`backend/scott_voice_install.py::asset_sources` сопоставляет новые исходные
пути с прежними ID пакета SDK. Пути установленных venv и моделей сохраняются.
Рабочий SDK обновляется штатной установкой из приложения; прямые правки его
библиотек обходят проверку владения файлами и не применяются.

Сохранённые профиль, поток, ускорение и буфер продолжают читаться backend.
Лаунчер не предлагает эти технические переключатели и не переписывает их при
открытии настроек. Изменение эталона, sampling или DSP требует отдельного
сравнения звука и слуховой оценки.

## Упаковка и диагностика

Установщики собираются скриптами `installer/build.py` и
`installer/build_linux.py`. `tools/check_release.py` проверяет Windows-пакет.
Для локальных проверок используется отдельный ValidationBuild с другим AppId.
Публичные теги и assets выпущенных версий не перезаписываются.

Архив поддержки собирается во вкладке **Логи**. Секреты редактируются, включая
старые файлы настроек удалённых компонентов. Технические этапы описаны в
[performance.md](performance.md), голос — в [voice.md](voice.md).

Исследовательские прототипы убраны из рабочих исходников. Предшествующая
публичная копия сохранена в локальном игнорируемом архиве
`reports/release-cleanup-2026-10-23/public-before.zip`; отчёты замеров остаются
в `reports/`. Приватные правила и история решений находятся в `AGENTS.md`,
`DEV_NOTES.md`, `PLAN.md` и `docs/internal/`.
