# Разработка и обслуживание

## Проекты

`ScottAI_qt` — текущий интерфейс C++/Qt, `backend` — Python/FastAPI.
Прежний настольный лаунчер Avalonia удалён; его исходники доступны в теге
`v2.0.0`. Мобильное приложение удалено из текущей ветки по решению автора.
Общие иконки и логотипы находятся в `assets/brand`.
Инструкция сборки Qt находится в [README лаунчера](../ScottAI_qt/README.md).

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ScottAI_qt/run.ps1
```

## Проверка backend

```powershell
py -3.13 backend/run_tests.py
py -3.13 backend/run_tests.py tests/test_scott_voice_process.py tests/test_tts_resilience.py tests/test_speech_cache.py -q
```

Runner создаёт временную копию исходников. Личная история, модели и ключи
в неё не переносятся. Тесты завершаются, затем эта копия удаляется.
Прямой pytest в рабочем backend может изменить файлы пользовательских данных.
Runner также включает `testing_guard.py`: попытки тестов читать или менять
рабочие данные, `.env` и аудиокеш отклоняются до доступа к файлам/SQLite.
Временные тестовые хранилища остаются доступны. Это защита от ошибок путей;
внешние процессы и произвольный недоверенный код нужно изолировать отдельно.

## Scott Voice

Отдельный процесс синтеза и кеш доступны для локальной проверки:

```powershell
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/check_service.py --recognize
```

Сначала нужно подготовить окружение и модели по
[инструкции эксперимента](../experiments/voice_design/README.md).
Работник загружает Qwen по первому запросу. Повторные запросы используют
проверенные WAV из `audio_cache/scott-voice`, в том числе после остановки
работника. Метаданные содержат ключ и SHA256, без текста речи.

Проверка создаёт три короткие реплики, при `--recognize` обращается только
к локальному Whisper. Она не включает микрофон, воспроизведение или
выполнение команд. Результат — `reports/voice-service/service.json`.

`--profile natural|restrained|scott|digital` выбирает обработку.
`--rms-norm` явно включает ускоренный экспериментальный способ вычислений.
Голос этого способа ещё требует оценки на слух. Эти проверки не меняют
выбранный голос приложения.

Qt использует `/voice/available` и `/voice/select`. Каталог включает
`available`, `reason`, `state`, `scott_profiles` и `scott_profile`.
Выбор характера: `{"voice":"scott-voice","profile":"restrained"}`.
Наличие файлов, контрольная сумма эталона и окружение проверяются до выбора.
Проверка CUDA выполняется в отдельном интерпретаторе, вне HTTP loop.

`backend/scott_voice_engine.py` связывает процессный клиент с рабочим
синтезатором. Выбор и резервный голос хранятся в `voice_config.json`, характер
Scott Voice — отдельным полем. Отмена запрещает и активный, и ожидающий
старый запрос; она не должна вызывать резервную озвучку. Таймауты/сбои имеют
30-секундную паузу повторных попыток. После 120 с простоя работник освобождается.

`speech_chunks` сокращает длинный первый фрагмент до границы фразы или слова
около 90 знаков; начало до 110 знаков остаётся целым. Последующие части —
до 180 знаков. Предел относится к подготовленному тексту; длинное отдельное
слово не разрывается дополнительно ради короткого начала. Оба пути озвучки
сохраняют порядок и проверяют отмену перед продолжением.

Измерения и сравнение записей находятся в `reports/voice-latency`.
Повторный прогон требует новой папки; рабочий кеш, настройки и эталон
не меняются. Синтез не включает микрофон или воспроизведение:

```powershell
py -3.13 experiments/voice_design/benchmark_latency.py --output reports/voice-latency-new
py -3.13 experiments/voice_design/evaluate_latency.py --output reports/voice-latency-new
```

Вторая команда требует локальный backend и обращается только к `/health`
и `/speech_to_text`. `--render-only` собирает страницу из сохранённых
результатов без повторного распознавания. Время до первого WAV измеряется
с запуском работника и загрузкой модели; оно не измеряет акустическую
задержку устройства. Разбиение уменьшает ожидание начала, но пока возможны
длинные паузы между частями. RMSNorm остаётся отдельным экспериментом.

### Потоковый синтез

`stream_voice.py` наблюдает выход звуковых кодов Qwen через forward hook.
Каждые 12 кадров декодирует доступный префикс, удерживая два последних кадра
у изменяющегося края. SDK, параметры генерации и эталон не меняются.
Фильтры цифрового характера, задержка и генератор модуляции сохраняют
состояние между блоками. Усиление выбирается один раз по первому блоку речи;
оно может отличаться от нормализации полного WAV.

Работник объявляет `stream_v1`; сообщения `chunk` содержат ID запроса, ключ,
номер, признак последнего блока и SHA256. Родитель сам определяет пути,
проверяет формат, порядок и суммарную длину. Очередь ограничена одним
ответом: до 128 блоков и два управляющих сообщения. Готовый кеш проверяется
отдельно и не содержит частичных записей. Временные WAV удаляются после
проигрывания либо остановки очереди.

`ScottVoice.speak_stream` ставит блоки в общий проигрыватель и ждёт последний.
Поколение запроса, тихий режим и отмена проверяются до каждого блока.
После частичного вывода сбой останавливает очередь без повторения ответа.
Старый работник без `stream_v1` до начала звука допускает полный синтез.
Время ожидания проигрывателя исключено из общего лимита синтеза;
поступление новых блоков этот лимит не продлевает.

API: `POST /voice/select` с `{"voice":"scott-voice","streaming":true}`.
Принимается только JSON boolean. Каталог возвращает `scott_streaming`,
а запись Scott Voice — `streaming_available`. Для включения нужна доступная
установка с поддержкой CUDA. Значение по умолчанию — false.

```powershell
py -3.13 experiments/voice_design/check_streaming.py --recognize --output reports/voice-stream-new
py -3.13 experiments/voice_design/check_streaming.py --recognize --fresh-profiles --output reports/voice-stream-new/fresh-profiles
py -3.13 experiments/voice_design/build_stream_preview.py --output reports/voice-stream-new
py -3.13 backend/run_tests.py tests/test_voice_streaming.py tests/test_voice_asset_update.py -q
```

Проверка требует локальный backend для STT, не использует микрофон,
проигрывание или команды и не меняет настройки. Повторный синтез требует
новой папки. Отчёт `reports/voice-streaming` сохраняет 18 проверенных WAV,
поток с измеренными паузами, отмену и контрольные суммы защищённых файлов.
Паузы в приложении всё ещё возможны; непрерывная речь требует ускорения модели.

### Необязательное ускорение

`scott_acceleration` в `voice_config.json` включает существующий вариант
RMSNorm в отдельном работнике. Значение по умолчанию false; принимается
только JSON boolean. API: `POST /voice/select` с
`{"voice":"scott-voice","acceleration":true}`. Каталог возвращает
`scott_acceleration`; запись Scott Voice — `acceleration_available` и
`accelerated`. Проверена NVIDIA/CUDA, другой движок не принимает этот параметр.

`preferred_config()` учитывает сохранённый выбор приложения. `default_config()`
остаётся исходным для установщика и измерений. На CPU предпочтение сохраняется,
но ускорение не применяется. `set_acceleration()` меняет конфигурацию,
увеличивает поколение запроса и закрывает прежний процесс без сброса счётчика.
После выключения создаётся новый работник с исходной RMSNorm. Старый ответ
и запрос, ожидавший блокировку, не должны пройти после смены режима.
Ключ кеша уже включает `rms_norm`; файлы обоих режимов сохраняются отдельно.

Сравнение использует
[PyTorch RMSNorm](https://docs.pytorch.org/docs/2.9/generated/torch.nn.functional.rms_norm.html).
Численные отличия могут менять выход генерации, поэтому требуется оценка
тембра на слух. Способ не меняет SDK на диске, модель или принятый эталон.

```powershell
py -3.13 experiments/voice_design/benchmark_stream_speed.py --output reports/voice-speed-new
py -3.13 experiments/voice_design/benchmark_stream_speed.py --order ba --output reports/voice-speed-new/reverse
py -3.13 experiments/voice_design/evaluate_stream_speed.py --output reports/voice-speed-new
py -3.13 backend/run_tests.py tests/test_voice_acceleration.py -q
```

Сначала ABBA, затем дополнительный BA: отдельные процессы и кеши для каждого
режима, один порядок фраз. STT запускается после всех замеров. Побайтово
одинаковые WAV распознаются один раз; сравнение также учитывает исходный текст.
`--render-only` строит отчёт из готовой проверки. Рабочие настройки,
микрофон, проигрывание и команды не используются. Повторный синтез требует
новой папки; актуальный отчёт — `reports/voice-stream-speed`.

### Накопление звука перед воспроизведением

`speech_buffer.py` откладывает первое воспроизведение до накопления звука.
Режимы: `immediate` (по умолчанию), `2s`, `4s`, `complete`. Сохраняются
в `scott_buffer`, независимо от профиля, потока и ускорения. API:
`POST /voice/select` с `{"voice":"scott-voice","buffer":"4s"}`. Другой
голос, неизвестная строка, null или число отклоняются до записи настроек.
Каталог возвращает `scott_buffer` и `scott_buffers` с названиями режимов.

`SpeechBuffer` удерживает не более 128 блоков. Последний блок выпускает
короткий ответ сразу, даже если порог не достигнут. Готовый кеш проходит
одним блоком. `ScottVoice.speak_stream()` объединяет первое накопление
в один временный WAV: PCM16/mono/24k копируется без фильтров и нормализации.
Временная папка принадлежит вызову и очищается после ожидания последнего
звука или отмены. Остальные блоки идут в общую очередь и используют один
выходной поток до конца фразы; подробности ниже.

До воспроизведения ошибка отбрасывает накопление и допускает прежний резерв.
После начала звук останавливается без полного повторения ответа. На каждом
блоке и после объединения сверяются поколения движка/проигрывателя и тихий
режим. Смена настройки отменяет старый запрос. Рецепт синтеза и ключ кеша
от буфера не зависят; исходники работника и отдельная среда не менялись.

```powershell
py -3.13 experiments/voice_design/build_buffer_preview.py --source reports/voice-stream-speed --output reports/voice-buffer-new
py -3.13 experiments/voice_design/build_buffer_preview.py --output reports/voice-buffer-new --render-only --recognize
py -3.13 backend/run_tests.py tests/test_speech_buffer.py tests/test_voice_streaming.py -q
```

Первая команда повторяет измеренные времена прихода блоков через рабочий
класс буфера, без нового синтеза. Вторая проверяет восемь WAV с паузами через
локальный STT. Сохраняются все WER, включая ошибки; успешный HTTP-запрос
не означает точность слов. Отдельный `--render-only` обновляет страницу
без STT. Отчёт — `reports/voice-buffering`: 72 расчёта, восемь WAV,
побайтовая сохранность речи, отдельно начальная задержка и сумма пауз.
Задержка устройства и акустические стыки здесь не измерялись.

### Ручная подготовка модели Scott Voice

В Qt доступны **Подготовить к речи**, отмена и **Освободить модель**.
Подготовка не запускается при старте приложения или выборе голоса.
Она загрузит Qwen и принятую опору без генерации WAV и воспроизведения;
потребуется память устройства. Стандартный таймер работника — 120 с простоя.
Состояние модели обновляется в настройках, включая её освобождение по таймеру.

- `GET /voice/prepare` — состояние задачи, `id`, сообщение и `model_loaded`.
- `POST /voice/prepare` с `{}` — запуск фоновой подготовки.
- `POST /voice/prepare/cancel` с `{"id":"..."}` — отмена или освобождение
  модели, принадлежащей этой задаче. Старый ID или новое поколение движка
  не должны остановить новую подготовку/озвучку.

Повторный запуск во время подготовки или синтеза возвращает 409;
недоступная установка — 400. Неизвестные поля и неверный ID — 422.
Запуск и отмена выполняются вне цикла событий FastAPI. Задача проверяет
поколение движка, на остановке backend освобождает принадлежащий ей работник.

IPC расширен необязательной возможностью `prepare_v1`: запрос содержит
`id/action/recipe`, ответ — `prepared/id/recipe`. Старый работник сообщает
`prepare_unavailable`; обычная озвучка остаётся совместимой.
В клиенте таймаут подготовки 180 с, обычный таймаут синтеза сохраняется.
`model_loaded` сбрасывается при остановке или завершении работника;
готовый кеш без загрузки модели не считается подготовленной моделью.
Изменённые скрипты отдельной установки обновляются штатным установщиком;
веса, эталон и окружение сохраняются.

```powershell
py -3.13 backend/run_tests.py tests/test_voice_prepare.py tests/test_scott_voice_process.py -q
py -3.13 experiments/voice_design/check_preparation.py --output reports/voice-preparation-new
py -3.13 experiments/voice_design/check_prepare_api.py --output reports/voice-prepare-api-new
```

На RTX 3060 проверены четыре пустых кеша в порядке холодный / подготовленный /
подготовленный / холодный. После запроса: 25,03 / 24,52 с на холодном,
13,89 / 14,19 с после предварительной загрузки 10,18 / 9,79 с. Все WAV
побайтово совпали с принятым образцом. Подготовка переносит загрузку во
время до вопроса, не ускоряет генерацию. Первый отдельный замер загрузки
занял 46,45 с; файловый кеш и нагрузка влияют на время.
Отчёт — `reports/voice-preparation/trial/index.html`.

`check_prepare_api.py` использует только ASGI-роутер подготовки и настоящий
работник, основной backend и сетевой сервер не запускаются. 1018 HTTP-запросов
без ошибок; отмена во время подготовки — 55 мс, освобождение готовой модели —
197 мс. Новый запрос сохраняет PID подготовленной простаивающей модели.
Автоматическое освобождение подтверждено завершением работника
и дочернего процесса; тестовый таймер сокращён до 0,5 с (фактическое завершение
около 0,7 с), таймер приложения остаётся 120 с. Ни синтеза, ни микрофона,
ни проигрывания в этой проверке нет; `reports/voice-preparation/api-retention/api.json`.

`_listener_handle()` останавливает прошлый звук с `preserve_prepared=True`.
Движок сохраняет модель только при отсутствии запросов подготовки/синтеза
и активности клиента. Счётчик запросов учитывает также ожидание до входа
в клиент. Активный запрос, явная остановка, пауза, тихий режим и освобождение
модели по кнопке по-прежнему закрывают работник. Сохранение простаивающего
клиента не меняет его поколение: задание подготовки продолжает владеть моделью.

### Один выходной поток для блоков Scott Voice

`SpeechPlayer.play_stream(path, token, last=False, generation=...)` использует
один blocking `sounddevice.OutputStream` для токена фразы: PCM float32,
mono, 24 кГц, выбранное устройство и текущая громкость. Очередь общая с
обычным проигрыванием. Готовый кеш или буфер, выпущенный целиком одним
блоком, остаётся на `play_and_wait()`; другой токен и обычный WAV закрывают
предыдущий поток после завершения звука.

Последний блок ждёт `stop()`/drain и закрытия устройства до возврата;
временные файлы до этого сохраняются. Отмена меняет поколение, освобождает
ожидающих, вызывает `abort()` и ставит закрытие в ту же рабочую очередь.
Закрытие выполняет владелец после выхода из `write()`. Повторная отмена
сохраняет ранее поставленные задачи закрытия. Ошибки устройства закрывают
поток, освобождают ожидание и отменяют старый хвост. `stream_stats` возвращает
копию накопленных счётчиков `opened`, `blocks`, `underflows`; это диагностика,
не оценка задержки модели.

`EchoReference.start_stream()` и `stream_block()` хранят недавние блоки
с временем начала и короткую опору для калибровки. `window()` собирает
нужное окно через границы, оставляет нули в реальных паузах. Калибровка
сохраняется между потоковыми ответами и сбрасывается при переходе между
обычным и потоковым выводом. Время оценивается по началу записи и длине
блоков; на физическом устройстве выравнивание ещё нужно проверить.

```powershell
py -3.13 backend/run_tests.py tests/test_stream_playback.py tests/test_speech_player.py tests/test_echo_in_listener.py -q
py -3.13 experiments/voice_design/check_output_stream.py --output reports/voice-output-new
```

Измеритель подменяет весь API устройства и доступ к настройкам перед запуском
рабочей очереди. Сверяет старую и новую подачу на 18 сохранённых потоках
в четырёх режимах буфера; новый синтез, STT, микрофон и колонки не запускаются.
PCM после float32 восстанавливается и сравнивается с прежними источниками,
чьи SHA256 и WER проверены. `reports/voice-output`: 72/72 совпадения,
396 → 72 открытия в имитации, все созданные потоки закрыты.
Задержка настоящего устройства, щелчки и эхо этой проверкой не измеряются.
Медленная генерация по-прежнему может вызывать ожидание следующих блоков.

### Проверка настоящего аудиоустройства

`check_audio_device.py` по умолчанию только перечисляет выходные устройства.
Для вывода сохранённой синтетической речи нужен `--play`; микрофон, модель,
backend и команды не запускаются. Используется выбранный выход, либо
`--device INDEX`, с отдельным множителем громкости теста (по умолчанию 25%).
Настройки приложения и системная громкость не записываются.

```powershell
py -3.13 experiments/voice_design/check_audio_device.py
py -3.13 experiments/voice_design/check_audio_device.py --play --output reports/voice-device-new
py -3.13 experiments/voice_design/check_audio_device.py --play --block-seconds 5 --modes cancel cancel_resume --output reports/voice-device-cancel-new
```

MME на этой машине принимает mono 24 кГц; WASAPI для этих наушников возвращает
ошибку частоты. Автоматическая смена устройства/драйвера не добавлялась.
Параметр `--latency low` предназначен только для отдельного сравнения,
рабочий проигрыватель сохраняет прежние настройки потока.

Настоящий MME не прерывал длинный блокирующий `write()` после `abort()`:
квитанция отменялась сразу, но очередь освобождалась через 4,64 с.
`SpeechPlayer` теперь пишет PCM порциями по `STREAM_WRITE_SECONDS = .1`,
проверяя поколение и отмену перед каждой записью. Поток один, порядок
и значения PCM прежние; эхоподавление получает исходный блок один раз.
`stream_stats.blocks` считает полностью переданные блоки, `underflows` —
число таких блоков, где хотя бы один write вернул флаг недостатка данных.
Этот флаг не является измерителем пауз: MME не выставил его даже при
намеренной задержке следующего блока.

`reports/voice-device/index.html`: отмена пятисекундного WAV освобождает
очередь за 14 мс в трёх повторах; новый поток в той же очереди открылся
через 11 мс. SHA256 переданного float32 совпадает с исходной речью с учётом
громкости. Проверены освобождение копий и закрытие всех потоков.
Время открытия и оценка `stream.latency` не означают измеренную задержку
звука в наушниках; акустическое эхо и стыки остаются проверкой на слух.

### Следующая фраза во время текущей речи

`ScottVoice.speak_stream_parts(chunks, force=False, cancelled=None)` отделяет
окончание синтеза фразы от окончания её воспроизведения. Это общий путь для
`ScottVoice.speak()` и `_play_voice_response()` в раннем режиме. Первый
ответ начинается с прежним буфером. После его подготовки запускается
следующая часть, а перед третьей ожидается завершение первой. Вперёд
подготавливается не более одной части, включая попадания в готовый кеш.
Работник и параметры синтеза не меняются; GPU выполняет один запрос за раз.

`SpeechPlayer.queue_file()` и `queue_stream()` возвращают квитанцию задания.
Её `result()` сообщает окончание/отмену/ошибку; `released` и `on_finished`
означают, что владелец очереди закончил читать и выводить этот файл.
Отмена может освободить вызывающего раньше завершения текущей записи.
Поэтому освобождение файлов выполняется отдельно, после задания; callbacks
не вызываются под блокировкой проигрывателя. Прежние `play()` и
`play_and_wait()` сохраняют возвращаемые bool и поведение ожидания.

`speech_pipeline.QueuedSpeech` копирует проверенные блоки и целые кешированные
WAV в принадлежащую фразе `.scott-prefetch-*`. Начальная группа буфера
объединяется тем же `join_wavs`. Копии не меняют PCM; исходные блоки работник
может удалить при завершении синтеза. Каждая копия удаляется после задания,
папка — после окончания подготовки и освобождения всех блоков. На фразу
не более 128 заданий. При отмене активный файл сохраняется до выхода из
записи; повторная отмена не теряет закрытие устройства.

Перед блоками и при ожидании проверяются поколения проигрывателя/движка,
тихий режим и отмена вызывающего. Прямой `speak()` сохраняет поколение,
снятое до разбиения текста. Отмена корутины ставит флаг фоновой работе:
сама `asyncio.to_thread()` поток не прерывает. Голосовая команда остановки
по-прежнему немедленно отменяет работник и аудиоустройство. После частичной
ошибки ответ целиком не повторяется. Ожидание всех частей удерживает защиту
слушателя от собственного ответа.

```powershell
py -3.13 backend/run_tests.py tests/test_speech_pipeline.py tests/test_stream_playback.py tests/test_voice_streaming.py -q
py -3.13 experiments/voice_design/check_prefetch.py --output reports/voice-prefetch-new
```

Измеритель использует реальный адаптер и очередь с полностью подменённым
устройством, движком и чтением настроек. 24 ответа из трёх сохранённых
фраз в четырёх режимах; 144 воспроизведения прежнего/нового пути побайтово
равны источникам, все потоки и временные файлы освобождены. Источники
ранее прошли STT с WER 0; повторного синтеза и STT нет. Времена на странице
рассчитаны по прежним замерам выдачи блоков. Копирование, нагрузка модели
и физический драйвер не измерены. Отчёт — `reports/voice-prefetch`.

`voice_cache.py` ограничивает только полные пары Scott Voice: 512 МиБ,
1000 записей, защита недавно использованного звука на 120 с. Лимит временно
превышается для защищённых файлов. Личные WAV, неизвестные файлы, ссылки,
незавершённые записи и эталоны не удаляются.

```powershell
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/check_integration.py
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/build_integration_preview.py
py -3.13 backend/run_tests.py tests/test_scott_voice_engine.py tests/test_voice_cache.py tests/test_scott_voice_process.py -q
```

Проверка интеграции требует запущенного backend. Она синтезирует тестовые
фразы, проверяет отмену настоящей модели, TTS API и STT. Она не воспроизводит
звук, не включает микрофон и не меняет рабочий выбор голоса.
Страница `reports/voice-integration/index.html` содержит отдельные копии WAV,
которые сохраняются после очистки аудиокеша.

Scott Voice может использовать экспериментальное окружение или отдельную
необязательную установку. Основной установщик теперь копирует только малый
пакет работника и принятого синтетического эталона, около 810 КиБ. Весов
и отдельного Python окружения в нём нет. Проверена NVIDIA/CUDA;
CPU можно отдельно исследовать через `SCOTT_VOICE_DEVICE=cpu`, поддержка
Qwen на AMD/CPU ещё требует проверки. Установка и проверка через Qt обновляют
каталог без перезапуска backend. После ручного изменения файлов или установки
через CLI перезапустите backend.

Эталон в исходниках находится в `assets/scott-voice/reference`: это точная
копия принятой синтетической записи с той же SHA256. Сборка малого пакета
не требует личных данных или локальных отчётов разработчика.

### Необязательная установка Scott Voice

В **Настройки → Голос** доступны «Установить Scott Voice», «Проверить»,
«Отменить» и повтор после отмены или ошибки. Установка работает в отдельном
процессе. Backend продолжает отвечать, интерфейс показывает текущий этап.
Выбор голоса после установки остаётся за пользователем.

Установщик автоматически готовит официальный CPython NuGet **3.13.7 x64**
внутри `voice-runtime/python`, затем создаёт изолированный venv.
Python не добавляется в PATH и не регистрируется в системе. Проверяются
закреплённая SHA256 архива и пути распаковки. Пакет содержит `venv` и `ensurepip`.
См. [официальное описание Python NuGet](https://docs.python.org/3.13/using/windows.html#the-nuget-org-packages).
Обычный embedded Python основной поставки запускает backend и установщик;
для нового голоса используется подготовленный отдельный Python.

Команды разработчика из корня ScottAI:

```powershell
# Показать версии, пути и команды; ничего не создавать и не скачивать.
py -3.13 backend/scott_voice_install.py --plan --auto-python
# Подготовить отдельное окружение, установить библиотеки и скачать Base.
py -3.13 backend/scott_voice_install.py --install --auto-python
# Проверить доступность; --deep дополнительно сверяет все контрольные суммы.
py -3.13 backend/scott_voice_install.py --check --deep
```

По умолчанию установка лежит в `voice-runtime` рядом с backend. Веса и
библиотеки заняли 7,1 ГиБ на проверенной машине; оставьте место для временных
загрузок. Нужны Windows x64, интернет и NVIDIA/CUDA. Переменная `SCOTT_VOICE_HOME` задаёт
другую папку; для разовой команды есть `--home`. При использовании `--home`
для нестандартного пути задайте тот же `SCOTT_VOICE_HOME` при запуске приложения.
Глобальные библиотеки, голосовые настройки и история не меняются.

SDK и библиотеки зафиксированы по проверенному окружению: Qwen TTS 0.1.1,
Transformers 4.57.3, PyTorch/TorchAudio 2.9.1+cu126. Модель закреплена за
revision `5d83992436eae1d760afd27aff78a71d676296fc`. Загрузчик сверяет SHA256
весов и Git blob ID конфигураций с официальной метадатой. Повреждённый
локальный файл скачивается заново; готовность отмечается после полной проверки.
Источники: [Qwen](https://github.com/QwenLM/Qwen3-TTS),
[PyTorch CUDA 12.6](https://pytorch.org/get-started/previous-versions/).

После сбоя повторите `--install`: завершённые файлы и загрузки используются
повторно. Чужая папка, другой рецепт или окружение с глобальными пакетами
отклоняются. Блокировка предотвращает параллельную установку. После аварийного
завершения блокировка снимается повторным запуском только после проверки
PID и времени создания прежнего владельца. Неизвестная блокировка сохраняется.
Дочерние команды не читают канал отмены. При закрытии backend принадлежащая
ему установка отменяется; готовые и частично загруженные файлы сохраняются.

Та же команда обновляет исходники уже готовой установки. Малый пакет
содержит девять ресурсов работника; ещё три файла клиента копируются
из backend. `scott-assets.json` хранит контрольные суммы установленных файлов.
Для первой версии используется проверенный `legacy-assets-v1.json`.
Обновляются только известные неизменённые скрипты; другие правки и замена
эталона отклоняются. Файлы подготавливаются отдельно, при ошибке записи
изменения откатываются. Веса, Python, библиотеки, кеш и настройки сохраняются.
Qt перед обновлением останавливает собственный синтез и обновляет каталог
после успеха. При ручном обновлении через CLI перезапустите backend.

Завершённая `voice-runtime` имеет приоритет над окружением эксперимента.
Неполная установка автоматически не выбирается. 7 октября проверена полная
установка нового окружения на машине разработчика: свежие библиотеки,
собственный Python, веса с официальными контрольными суммами. Имеющиеся веса
использованы повторно после проверки; скачивание отсутствующих и повреждённых
файлов отдельно покрыто тестами. Проверка на другом чистом компьютере остаётся.

API: `GET /voice/install`, `POST /voice/install` с `action: install|check`,
`POST /voice/install/cancel` с ID текущего задания. Пути и команды через API
не принимаются. Ошибки старого задания не отменяют новую установку.
Ход работы сообщается строками JSON; обычные логи pip не идут в UI.

`experiments/voice_design/check_optional_install.py` проверяет новое окружение
на синтетических WAV через STT без микрофона, проигрывания и команд.
Результаты и образцы — `reports/voice-setup`; новые фразы пока требуют
десятков секунд синтеза, попадание в кеш — около 4 мс.

## Очистка

```powershell
# Показать перечень.
powershell -NoProfile -ExecutionPolicy Bypass -File tools/clean_project.ps1 -OldReleases
# Удалить перечисленные временные файлы и старые дистрибутивы.
powershell -NoProfile -ExecutionPolicy Bypass -File tools/clean_project.ps1 -OldReleases -Apply
```

Удаляются известные кеши Python/pytest/ruff и временные SDK Resolver backups.
С `-OldReleases` старый дистрибутив удаляется только при наличии текущей
версии `VERSION.json` для того же варианта и платформы. Неизвестные имена
и платформы без текущего дистрибутива сохраняются.

Скрипт проверяет границы проекта и не следует по ссылкам. Он исключает
данные, ключи, модели, виртуальные окружения, отчёты, логи, аудиокеш и рабочие
сборки. Перечень сохраняется в `reports/project-cleanup.json`.
Кеши могут появиться снова при обычном запуске — это нормальная работа.
