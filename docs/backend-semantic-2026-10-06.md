# Смысловой поиск памяти — 6 октября 2026

## Результат

История и факты подбираются по словам и по смыслу. Локальная E5 обрабатывает
тексты на CPU; облачных запросов для поиска нет. Загрузка модели и индексация
идут в фоне, ошибки оставляют доступным прежний поиск.

На неизменённом корпусе из 12 русских вопросов и дополнительном примере
об оформлении окна найдены **11 из 13** нужных разговоров. Поиск по словам
нашёл 4 из 13. Среди девяти запросов без общих слов с нужной записью поиск
по смыслу нашёл семь. У 10 из 13 вопросов лучший смысловой кандидат был
нужным разговором. У четырёх посторонних тем кандидаты отсутствовали.
Это небольшой диагностический корпус, не общая оценка точности.

Вопрос «Что мы выбрали для оформления окна?» нашёл Glass в разговоре
о дизайне лаунчера без пересечения поисковых слов. После повторного создания
объекта памяти использованы сохранённые векторы. Подбор старого факта с Glass
также прошёл, хотя после него добавлены 50 посторонних фактов.
Очистка истории удалила разговоры, векторы и отметки индексации.

Среднее время двух поисковых вызовов на один вопрос — 10,7 мс,
максимум — 11,4 мс, на вымышленной истории из 20 разговоров.
Большие архивы требуют отдельного измерения. Модель и токенизатор занимают
135 429 554 байта (около 129 МиБ); загрузка из готового кэша — около секунды.

## Оставшиеся пропуски

- «Как оформить интерфейс программы?» — нужный разговор о дизайне оказался
  ниже четырёх включаемых пар. Запрос слишком широко сопоставился с другими
  техническими темами.
- «Какая настройка управляет случайностью генерации?» — модель не связала
  вопрос с сохранённой температурой 0,4 достаточно уверенно.

Первая проверенная MiniLM-модель дала 8/12 и не подошла для этих русских
запросов. E5 дала лучший результат на том же корпусе. Порог 0,78 добавлял
ложные совпадения для фотосинтеза и не устранял два пропуска, поэтому выбран
более строгий 0,80. Корпус не переписывался, ошибки не удалялись.

## Реализация

- `semantic_memory.py`: фиксированная ревизия E5, ONNX на CPU, два потока,
  среднее по токенам с маской, нормирование, префиксы query/passage.
- История: индекс фрагментов и отметки готовых разговоров в SQLite.
  Фоновые задачи не держат транзакцию при вычислении векторов.
  Перед записью проверяется fingerprint в транзакции с `BEGIN IMMEDIATE`:
  очистка и повторное использование ID не прикрепляют старый вектор
  к новому разговору.
- Поиск: объединение словесных и смысловых кандидатов, сохранение лимита
  четырёх завершённых пар и 2000 символов. Векторы читаются блоками;
  весь архив не копируется в одну матрицу в оперативной памяти.
- Факты: ограниченный кэш в RAM, сброс с поколением при изменении/удалении.
  Профиль и стиль ответов сохраняют прежний приоритет.
- API `/memories`: дополнительный объект `semantic_search` со статусом
  и счётчиками без текста истории.
- `SCOTT_SEMANTIC_MEMORY=0`: поиск по словам без загрузки модели.

Поиск не использует PyTorch, CUDA или ROCm. Драйверы и библиотеки речи
на этой машине не изменялись. Проверена Windows x64 на Intel i5-13400F;
смысловая модель не использует NVIDIA GPU.

## Проверки и воспроизводимость

10 автоматических проверок: перезапуск, отсутствие общих слов, фильтрация
удалённого факта, очистка и её откат, очистка во время индексации с повторным
ID, удаление факта во время кодирования, повреждённый/чужой вектор,
отсутствие модели, ошибка inference и корректная маска padding/префиксы.
Все используют подменённый encoder и временные файлы; сеть и настоящая
модель в pytest отключены.

Реальная модель проверена через `backend/check_semantic_memory.py`:

```powershell
py -3.13 backend/check_semantic_memory.py --download
```

Окончательный отчёт: `reports/backend-semantic-2026-10-06/final/report.json`.
Диагностический инструмент возвращает 1 из-за двух сохранённых пропусков.
История в отчёте вымышленная; пользовательская память и API Token
не использовались. Микрофон, озвучка, исполнение команд и облачная LLM
не запускались.

Полный автономный набор backend: **1409 passed, 7 deselected, 3 warnings**,
244,64 с. Лог `reports/backend-semantic-2026-10-06/pytest-complete.log`:

```powershell
py -3.13 -m pytest backend/tests -q -m 'not integration and not slow'
```

После запуска приложения существующие 579 разговоров проиндексированы
локально, счётчик истории остался 579, фактов — 0, предупреждений нет.
В отчёт сохранены только состояния и числа. После готовности индекса
30 проверок `/health` дали среднее 2,86 мс и максимум 6,67 мс.
Эти замеры относятся к готовому индексу, не к времени его построения.
Qt отвечает, backend онлайн, прослушивание и озвучка не активны.
Метаданные: `reports/backend-semantic-2026-10-06/live-state.json`.

В настройках ответов по-прежнему указан `nex-agi/nex-n2.5-pro:free`.
6 октября его нет в публичном каталоге OpenRouter; для ответов нужно
выбрать доступную модель. Локальная модель поиска E5 работает независимо
от этого выбора.
