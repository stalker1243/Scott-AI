# Приложения и окна

В текущих исходниках команды работают из чата, мини-чата питомца и через
микрофон. Отдельно включать режим действий не нужно. Эти изменения ещё не
входят в опубликованную версию 2.0.1.

## Примеры

| Просьба | Результат |
| --- | --- |
| «Открой Firefox» | Найти установленное приложение и запустить |
| «Покажи установленные программы» | Показать первые 60 записей каталога |
| «Обнови список приложений» | Перечитать каталог после установки программы |
| «Покажи открытые окна» | Показать заголовки доступных окон |
| «Переключись на Spotify» | Выбрать открытое окно |
| «Сверни окно Telegram» | Свернуть выбранное окно |
| «Разверни Firefox» | Развернуть окно |
| «Восстанови окно» | Восстановить активное окно |
| «Покажи рабочий стол» | Отправить сворачивание доступным окнам |
| «Закрой все окна» | Отправить обычный запрос закрытия |
| «Закрой все окна кроме Firefox и Telegram» | Сохранить окна названных приложений |
| «Покажи кнопки в Spotify» | Получить доступные названия элементов интерфейса |
| `Нажми кнопку «Воспроизвести» в Spotify` | Найти одну кнопку по точному названию и нажать |

Если подходят несколько окон, Скотт попросит уточнить заголовок. Для
приложения с несколькими окнами можно назвать нужный документ. В команде
без названия используется активное окно. Системные оболочки, окна Скотта
и родительские процессы backend исключены из управления.

Закрытие не гарантирует немедленного исчезновения окна: приложение может
предложить сохранить документ или отказаться. Скотт сообщает число
отправленных запросов. Массовая команда обрабатывает до 64 окон за раз.

## Поиск программ без отдельных команд

Windows использует App Paths, исполняемые файлы из PATH, ярлыки меню «Пуск»
и каталог Get-StartApps, включая приложения Microsoft Store. Linux читает
`.desktop`-записи, в том числе пользовательские, Flatpak и Snap. Существующий
поиск macOS использует каталоги `.app` и Spotlight.

В Linux учитываются абсолютные `XDG_DATA_HOME` и `XDG_DATA_DIRS`.
Пользовательская запись имеет приоритет; `Hidden=true` скрывает одноимённую
системную запись. Правила каталогов описаны в
[спецификации XDG](https://specifications.freedesktop.org/basedir/latest/).

Каталог кешируется на две минуты. При неудачном поиске устаревший снимок
может обновиться раньше; частые повторные сканирования ограничены.
Пустой ответ временно недоступного источника сохраняет предыдущий снимок.
Нечёткий поиск и транслитерация помогают с произношением названия.

## Взаимодействие с интерфейсом

В Windows Скотт использует UI Automation: приложение само предоставляет
названия кнопок и способ нажатия. Для обычных кнопок Win32/WinForms есть
дополнительный путь через стандартный оконный интерфейс. Отдельный список
команд под каждую программу не требуется.

Пока доступны перечисление элементов и нажатие одной кнопки по названию.
Ввод текста, чтение документов из окна, перетаскивание, распознавание экрана
и самостоятельное планирование цепочки действий сюда не входят. Поля
пароля и содержимое полей ввода не читаются. При одинаковых названиях
нажатие отменяется. После тайм-аута автоматического повторного нажатия нет.

Не все программы предоставляют нужные элементы: игры, нестандартные
интерфейсы и окна с повышенными правами могут быть недоступны. Реальное
название кнопки зависит от языка и версии приложения. Spotify и другие
сторонние приложения требуют отдельной проверки на установленной версии.

| Среда | Запуск программ | Управление окнами | Кнопки |
| --- | --- | --- | --- |
| Windows | Да | Win32 | UI Automation / стандартные кнопки |
| Linux X11 | Да | Нужны `wmctrl` и оконный менеджер с EWMH | Пока нет |
| Linux Wayland | Да | Общий доступ ограничен композитором | Пока нет |
| macOS | Существующий поиск `.app` | Пока нет | Пока нет |

Справка по платформенным механизмам:
[Windows WM_CLOSE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-close),
[UI Automation](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-controlpatternsoverview),
[EWMH](https://specifications.freedesktop.org/wm/latest-single/).

## Устойчивость backend

Медленные модели, команды и запись памяти используют отдельные ограниченные
пулы. Истёкший запрос освобождает место только после фактического завершения
работы: повторные запросы не создают бесконечную очередь потоков.
Недоступный обработчик возвращает понятную ошибку.

Ожидание модели больше не удерживает общий замок истории. Можно читать
переписку и работать с другими диалогами. В чате после тайм-аута поздний ответ
модели не добавляется в историю. Ошибка записи дополнительной памяти
не отменяет уже выполненную команду.

Нативное управление окнами выполняется в отдельном процессе с тайм-аутом.
Его аварийное завершение не завершает backend. `/health` показывает число
занятых обработчиков, тайм-аутов и отклонённых запросов по каждому пулу.
Это устраняет проверенные причины зависаний, но не заменяет проверку
конкретных драйверов, устройств и внешних приложений.
