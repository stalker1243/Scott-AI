# Скорость и диагностика ScottAI

Время ответа складывается из ожидания конца фразы, распознавания, обработки
команды, запроса к ИИ-модели, синтеза и вывода звука. Эти этапы нужно
проверять отдельно: более быстрый вывод текста не означает более быстрый голос.

## Подготовленные изменения

- Whisper подготавливает декодер первого запроса на поддерживаемой NVIDIA CUDA.
- Каталог приложений готовится заранее и повторно используется при командах.
- Следующая часть голосового ответа может синтезироваться во время текущей.
- Готовые реплики озвучиваются из проверенного кеша.
- Установка использует проверенные загрузки повторно и продолжает прерванные.

В контрольном сравнении первого Whisper-запроса после готовности медиана
снизилась с 1,364 до 0,407 с. Подготовка вместе с первым запросом заняла
7,052 и 7,521 с: часть работы перенесена раньше, весь холодный запуск
быстрее не стал. Это RTX3060, OpenAI Whisper turbo, по три наблюдения
в каждом из трёх процессов на вариант; фоновые тяжёлые задачи были закрыты.
Результат не описывает другие видеокарты и полный разговор через микрофон.

Scott Voice может генерировать длинный ответ медленнее его звучания.
Проверка готового аудио и потока через настоящий драйвер 23 октября прошла
без сообщений о нехватке данных; пользователь услышал оба варианта плавно.
Она использовала заранее подготовленную речь и не доказывает отсутствие
пауз при живой генерации. Технические переключатели в лаунчере убраны,
сохранённые параметры принятого голоса применяются как раньше.

## Собрать сведения о проблеме

Во вкладке **Логи** сохраните архив после проблемного запроса. Полезно
указать, задержался ли текст, первое слово или продолжение речи, и была ли
запущена игра или другая тяжёлая задача. Токены API присылать не нужно.

Локальный `GET /timings` возвращает агрегаты этапов. `tools/analyze_timings.py`
сравнивает технические записи. Метрики `voice.first_*` начинаются с закрытия
записи: ожидание конца фразы VAD находится до этой точки. Передача буфера
устройству не измеряет акустическое начало. Вложенные этапы перекрываются,
их длительности нельзя складывать.

### Как различать паузы в голосе

Для голосового запроса в технической сводке есть раздел `playback`:

- `driver_underflow_blocks` — число потоковых блоков, при передаче которых
  драйвер сообщил о нехватке данных. Для готового файла этот счётчик не снимается.
- `max_estimated_supply_gap_ms` — оценка опоздания следующего блока относительно
  длительности уже переданного звука. Это сведения о подаче, а не запись динамиков.
- `max_inter_output_gap_ms` — ожидание между выходными частями одного ответа.
  Оно может включать подготовку следующей фразы и обычные паузы между предложениями.
- `aborted_sessions` — прерванные выходные сеансы, например при остановке ответа.

Эти признаки помогают выбрать дальнейшую проверку. Нулевые счётчики не
доказывают отсутствие слышимого дефекта: нужна оценка разговора через настоящее
устройство. Запись содержит технические числа и случайный ID запроса, без
текста команды, аудиозаписи, путей файлов и названия устройства.

## Размер установки

Основной объём занимают веса нейросетей и библиотеки, а не Python-файлы
команд или Qt-интерфейс. Чат и распознавание устанавливаются отдельно от
Scott Voice; голос и браузер готовятся по запросу. Удаление исследовательских
скриптов упрощает проект, но само по себе не уменьшает веса моделей.
Подробнее — [подготовка приложения](installation.md).
