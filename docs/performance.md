# Работа над скоростью

Обновление ScottAI 2.1.1 посвящено отклику команд, чата и голоса.

## Что меняется

- Основной чат и мини-чат получают текст по мере генерации. Кнопка отправки
  во время запроса останавливает ожидание. Черновик и вложения сохраняются
  при ошибке или остановке. Незавершённый ответ модели не записывается в историю.
- Каждый запрос использует снимок выбранного провайдера и модели.
  Независимые диалоги могут обращаться к модели параллельно; лимит работников
  сохраняется. Один диалог по-прежнему принимает только один запрос за раз.
- Голос может начать первую законченную фразу до завершения ответа модели.
  Фрагменты кода и незаконченные предложения ждут полного ответа.
  После остановки начатая фраза целиком повторно не запускается.
- Обычные команды без новых сведений о пользователе обходятся без чтения
  настроек автоматической памяти. Явные факты сохраняются прежним способом.
  Проверка удалённых сведений использует один снимок настроек на подбор контекста.
- Просроченный каталог возможностей OpenRouter обновляется в фоне при обработке
  сообщения. На вкладке моделей остаётся явное обновление каталога.
  Неподтверждённая поддержка вложений по-прежнему не считается разрешением.
- HTTP-потоки DeepSeek, Anthropic и OpenRouter используют постоянные сессии
  работников. Внешний API Token, модель и профиль Scott Voice сохраняются.

Поддерживаются текстовые потоки OpenAI, Groq, DeepSeek, Anthropic и OpenRouter.
Ошибка после начала ответа завершает поток с понятным сообщением; запрос
автоматически повторно не отправляется. Генерация изображений возвращает готовый
результат, как прежде. Текст модели сам по себе не исполняется как команда.

## Как измеряется отклик

`GET /timings` показывает медиану и p95 этапов. В журнале `timings.jsonl`
сохраняются длительности и случайный идентификатор запроса, без текста сообщений
и API Token. Журнал входит в диагностику приложения.

- `chat.first_text` / `voice.first_text`: время до первого фрагмента текста.
- `voice.first_sentence_ready`: первая целая фраза передана на озвучивание.
- `voice.first_audio_ready`: синтез подготовил первый файл или буфер звука.
- `voice.result_ready`: результат команды готов до дополнительного архивирования.
- `chat.total` / `voice.total`: запрос завершён или остановлен.
- `memory.observe`: проверка и сохранение явно сообщённых сведений.

Подготовленный звук ещё не означает, что он уже прозвучал в динамиках:
буферизация устройства измеряется отдельно. Для распознавания остаются прежние
замеры STT и адаптивное определение конца фразы.

Сравнивать следует одинаковые запросы и оборудование, отдельно после запуска
и после прогрева. Синтетические задержки в тестах проверяют порядок выполнения
и отмену; они не показывают скорость реального провайдера, Qwen или аудиоустройства.

## Ограничения

Потоковая выдача уменьшает ожидание начала ответа. Полное время генерации
по-прежнему зависит от модели, длины ответа и сети. Scott Voice может
синтезировать новые фразы медленнее их воспроизведения. Принятый профиль B,
настройки ускорения и раннего синтеза, веса и эталон голоса не изменяются.
Автоматический прогрев необязательного Scott Voice не включается.

Остановка ожидания команды не отменяет уже выполненное действие в приложении.
При сетевой ошибке проверьте результат перед повтором. Ограничения работников,
проверки доступа, подтверждения и защита от повторного выполнения сохраняются.

## Документация протоколов

Потоковый режим использует существующий `POST /chats/{id}/messages`,
поле multipart `stream=true`. События SSE: `delta` с полем `text`,
`done` с обычным результатом API, `error` с безопасным кодом и подсказкой.
Старые клиенты без этого поля получают обычный JSON. Сервер отправляет
комментарии keepalive; очередь между моделью и HTTP ограничена.

Форматы провайдеров сверены с официальной документацией:
[OpenAI](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming),
[OpenRouter](https://openrouter.ai/docs/api_reference/streaming).
