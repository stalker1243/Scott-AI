# Новый голос Scott: локальный эксперимент

## Отдельный процесс и кеш

Первый этап подключения Scott Voice подготовлен: клиент
`backend/scott_voice_process.py` и работник `voice_worker.py`. Клиент не
загружает Torch и запускает работника только при отсутствии готового WAV.
Модель и эталон загружаются по первому синтезу, затем используются повторно.

```powershell
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/check_service.py --recognize
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/build_service_preview.py
```

Нужно подготовленное окружение и Base, описанные ниже. Реплики «Готово»,
«Слушаю» и «Соединение восстановлено» сохраняются в
`audio_cache/scott-voice`. Повторный запрос проверяет SHA256 и формат WAV;
готовая запись доступна без запуска работника. Метаданные не содержат текст.
Исходная запись хранится отдельно от обработки: смена цифрового характера
для того же текста не требует нового нейросетевого синтеза.

Окраска задаётся через `--profile natural|restrained|scott|digital`.
Ускорение RMSNorm остаётся явной пробой `--rms-norm`. По умолчанию используется
принятый режим синтеза Base с умеренной цифровой окраской для сравнения.
Выбранный голос рабочего приложения эти команды не меняют.

Таймаут или отмена завершают дерево принадлежащих клиенту процессов,
включая Windows venv перенаправление. После 120 с простоя процесс
освобождается, WAV сохраняются. Библиотеки пишут в stderr, JSON протокол —
в stdout; зависший или повреждённый ответ не выдаётся как готовая запись.
Клиент нужно закрывать через `close()` либо контекстный менеджер.

Результат 6 октября: три реплики распознаны Whisper без ошибок слов,
повторное получение кеша около 1–2 мс, родитель не загрузил Torch,
backend оставался доступен. Проверено 27 выбранных backend тестов.
Отчёт — `reports/voice-service/service.json`. Следующий этап — подключение
к голосовому каталогу backend, резервному синтезатору и настройкам Qt.
Страница ручного прослушивания коротких ответов — `reports/voice-service/index.html`.

Три исходных мужских голоса: мягкий, нейтральный и чуть строгий. Каждый
создаётся Qwen3-TTS VoiceDesign по описанию из `profiles.json` и читает
одинаковый текст. Образцы сохраняются в `reports/voice-design`.

## Запуск на текущем компьютере

Windows, Python 3.13, PyTorch 2.9.1+cu126, RTX 3060 12 ГБ.
Окружение `.venv` использует установленный PyTorch; остальные зависимости
устанавливаются в эту папку. TorchAudio должен совпадать с версией PyTorch.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File experiments/voice_design/setup.ps1
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/download_model.py
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/generate_samples.py
py -3.13 experiments/voice_design/create_baseline.py
py -3.13 experiments/voice_design/evaluate_samples.py
py -3.13 experiments/voice_design/select_reference.py firm
py -3.13 experiments/voice_design/build_preview.py
```

Откройте `reports/voice-design/index.html`, чтобы прослушать три WAV.
Воспроизведение начинается после нажатия. Микрофон и исполнение команд
для создания или проверки записей не включаются.

Синтез использует SDPA из PyTorch, отдельная сборка FlashAttention для
Windows не нужна. Для медленного эксперимента на процессоре можно передать
`--device cpu`. Выбор текущего голоса приложения этот эксперимент не меняет.

## Модель и записи

Официальная модель [Qwen3-TTS-12Hz-1.7B-VoiceDesign](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign)
занимает около 4,2 ГиБ вместе с речевым токенизатором. Загрузчик фиксирует
revision и сохраняет её в `models/design/scott-model.json`; повторный запуск
использует ту же версию. Файлы загружаются через Hugging Face без API Token.
Крупные веса скачиваются HTTP-частями по 16 МиБ с возобновлением. Перед
использованием проверяется полный SHA-256 из официальной LFS-метадаты.
Синтез после загрузки работает локально. Модели и WAV исключены из Git.

`samples.json` сохраняет описания, seed, подготовленный текст, длительность,
время генерации и пик выделенной видеопамяти процесса. Громкость образцов
выравнивается с ограничением пиков. Темп, высота и тембр после синтеза
не изменяются. В текст не передаются специальные знаки ударений Silero.

`recognition.json` содержит результат Whisper turbo. Он помогает обнаружить
пропущенные или добавленные слова. Точность ударений и приятность тембра
нужно оценивать на слух; совпадение распознанного текста их не измеряет.

## Следующий этап

Пользователь выбрал **«Чуть строгий»** 6 октября 2026 года. Выбор записан в
`selected_voice.json`. Команда `select_reference.py firm` сохраняет точную
копию записи в `reports/voice-design/reference/scott-reference.wav`,
SHA-256, подготовленный текст и параметры модели в соседний `reference.json`.
Этот эталон сохраняется отдельно от повторной генерации трёх образцов.

Нужно проверить ещё несколько реплик на основе выбранного голоса.
Для постоянного тембра используется связка VoiceDesign → Base с сохранённой
эталонной записью, описанная в [документации Qwen](https://github.com/QwenLM/Qwen3-TTS#voice-design-then-clone).
Небольшая модель Base 0.6B предусмотрена в загрузчике (`--kind base`).
Перед подключением к backend нужно измерить задержку и память при совместной
работе с Whisper. Silero остаётся резервным движком.

## Проверка выбранного голоса на Base 0.6B

```powershell
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/download_model.py --kind base --workers 16
py -3.13 experiments/voice_design/benchmark_silero.py
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/benchmark_base.py
py -3.13 experiments/voice_design/build_base_preview.py
py -3.13 experiments/voice_design/build_preview.py
```

Нужен запущенный локальный backend на `http://127.0.0.1:8000`.
`benchmark_base.py` допускает только локальный адрес. Результаты и страница
сравнения сохраняются в `reports/voice-base`. Страница первого сравнения
получает ссылку на новые реплики. Обе страницы открываются без сервера.

Base использует сохранённый WAV и его точный текст в ICL-режиме. Эталон
кодируется один раз, затем подготовленный prompt используется для всех
реплик. Параметры генерации, версия модели, SHA-256 эталона и время его
подготовки записываются в `base.json`.

В `trial_cases.json` шесть синтетических реплик: исходный текст, короткий
ответ, технические названия, числа, вопрос и развёрнутое объяснение. Они
синтезируются новым голосом и текущим Евгений/Спокойный. Для Silero отдельно
прогреваются все длины фраз; оба скрипта используют четыре потока CPU.
Громкость сопоставима, темп и высота после синтеза сохраняются.

Распознавание идёт через `/speech_to_text` работающего backend. Этот API
обрабатывает только WAV и возвращает текст; `/ask` и голосовой исполнитель
не вызываются. Поэтому тесты не добавляют диалоги и не исполняют команды.
Вторая копия Whisper в видеопамять не загружается. Две дополнительные
реплики синтезируются одновременно с распознаванием отдельной записи.
Во время проверки опрашивается `/health` и расход памяти всей видеокарты.
Флаг `--greedy-control` дополнительно проверяет исходную реплику без
случайного выбора токенов. Это дополнительный образец, а не автоматическая
смена режима выбранного голоса. По умолчанию эта проба пропускается:
в первом замере она дала почти тихий сигнал и заняла 140 с.

`synthesis_seconds` Base — время создания полного WAV, с синхронизацией CUDA,
без чтения эталона на каждом запросе. Этот SDK не возвращает первые звуковые
фрагменты, поэтому время до начала потокового воспроизведения здесь не
измеряется. Тайминг Silero дополнительно включает обработку характера и
запись WAV. Проценты ошибок слов учитывают нормализацию чисел, известных
сокращений, регистра и «ё». Они не измеряют ударения и сходство тембров.

`vram_allocated_peak_gib` — выделенная PyTorch память процесса Base во время
генерации; `gpu_observed_used_peak_gib` — выборочный пик всей видеокарты,
включая backend, остальные процессы и рабочий стол. Эти значения имеют
разный смысл и не вычитаются друг из друга как точный расход Whisper.

### Результат Base: 6 октября 2026 года

Модель `Qwen/Qwen3-TTS-12Hz-0.6B-Base`, revision
`5d83992436eae1d760afd27aff78a71d676296fc`. Веса вместе с токенизатором —
2,34 ГиБ. Совпадающий токенизатор скопирован из VoiceDesign после проверки
официального SHA-256. Полный SHA-256 основных весов также проверен.
После сетевых ошибок загрузка продолжена с недостающих 13 блоков.

RTX 3060 / BF16 / SDPA / четыре потока CPU: загрузка Base — 2,24 с,
подготовка эталона — 0,98 с; прогрев учитывается отдельно.

| Реплика | Длина Base | Синтез Base | Синтез Евгений/Спокойный |
| --- | ---: | ---: | ---: |
| Исходный текст | 15,60 с | 36,61 с | 0,196 с |
| Короткий ответ | 4,96 с | 11,97 с | 0,067 с |
| Технические названия | 8,88 с | 20,77 с | 0,089 с |
| Числа | 10,96 с | 25,69 с | 0,110 с |
| Вопрос | 8,00 с | 19,04 с | 0,097 с |
| Объяснение | 13,76 с | 32,47 с | 0,143 с |

Whisper распознал **6 из 6** основных реплик Base без ошибок слов.
У текущего голоса — 5 из 6; в технической реплике распознавание пропустило
предлог «к». Это результат короткого синтетического корпуса, а не общая
оценка качества русского произношения. Пользователь прослушал образцы Base
и подтвердил, что тембр подходит. Выбранный режим сохранён в `selected_voice.json`.

Пик выделенной PyTorch памяти Base — 2,75 ГиБ на основных репликах.
Контрольный VoiceDesign с теми же потоками и прогревом: 16,64 с речи за
41,14 с, пик 4,38 ГиБ. Его WAV побайтово совпал с выбранным эталоном.
Среднее отношение времени синтеза Base к длине аудио — 2,364.
Экономия памяти получена; задержка для ежедневного ассистента остаётся большой.

Одновременный синтез и распознавание прошли на двух репликах: 12,33 с и
21,32 с синтеза против 11,97 с и 20,77 с в последовательной проверке.
Обе новые записи и обе распознаваемые одновременно записи получили WER 0.
Во всём прогоне `/health`: 1132 успешных опроса, ошибок нет, p95 — 0,018 с.
Выборочный пик использования памяти по `torch.cuda.mem_get_info` — 8,96 ГиБ;
отдельный опрос `nvidia-smi` во время генерации показал 9914 МиБ занято.
Это разные моменты измерения, поэтому выборочный пик не является точным
максимумом расхода всей видеокарты.

Дополнительный greedy-режим не дал разборчивой речи: 61,36 с почти тихого
сигнала, 140,42 с генерации, распознавание вернуло пустой текст/HTTP 400.
Обычный sampling-режим остаётся подтверждённым вариантом прототипа.

Следующий этап — профилировать и ускорять сам синтез, затем проверять
воспроизведение по частям. При текущем времени генерации, большем длины
аудио, одно потоковое воспроизведение не обеспечит непрерывный ответ.

## Scott Voice: цифровой характер

По просьбе пользователя подготовлены три степени роботизированной окраски
подтверждённого голоса «Чуть строгий»: **Сдержанный**, **Scott Voice** и
**Цифровой**. Сравнение — `reports/scott-voice/index.html`. На странице
есть исходный голос и три обработанных варианта каждой из трёх реплик:
короткий ответ, числа и технические названия.

Параметры находятся в `robotic_profiles.json`. Обработка модулирует нижнюю
часть спектра, сохраняет верхнюю часть с согласными и добавляет короткий
металлический резонанс. Речь не растягивается и не транспонируется.
Scott Voice — собственный характер на основе выбранного синтетического
тембра. Обработка не меняет интонацию на новую актёрскую подачу.

```powershell
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/create_scott_voice.py --check-stt
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/build_scott_preview.py
```

`--check-stt` использует только `/speech_to_text` работающего локального
backend. Без флага WAV создаются без обращения к приложению. Все девять
записей 6 октября 2026 года получили WER 0 на этих фразах. Проверены
PCM16/моно/24 кГц, конечность сигнала, сохранение числа отсчётов, громкость,
отсутствие перегрузки и побайтовая воспроизводимость обработки.
Проверка распознавания не заменяет выбор тембра на слух.

После загрузки SciPy обработка этих записей занимает около 5–23 мс.
Первый вызов в исходном отчёте включает импорт SciPy и занимает 1,09 с.
Задержка нейросетевого синтеза измеряется отдельно. Рабочий голос
приложения пока остаётся Евгений/Спокойный.

### Проверка скорости

```powershell
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/profile_base.py
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/benchmark_speed.py
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/benchmark_speed.py --output reports/voice-speed-efficient --candidates original efficient_kv efficient_rms
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/benchmark_speed.py --output reports/voice-speed-rms --candidates original rms
experiments/voice_design/.venv/Scripts/python.exe experiments/voice_design/build_speed_preview.py
```

Профилировщик по умолчанию собирает начальную обработку и первые два
вызова предсказателя звуковых кодов. `--full-trace` собирает весь синтез
и может занять много оперативной памяти. Время с профилировщиком не
используется для оценки ускорения. Результаты — в `profile.json` и
`speed.json` соответствующей папки отчёта.

Оптимизации применяются временно внутри отдельного процесса: отключение
неиспользуемых промежуточных состояний, явное повторение KV голов для
выбора другого SDPA ядра, ограничение набора ядер и встроенная RMSNorm.
SDK и работающий backend не меняются. После отдельного прогрева каждого
варианта выполняются два замера одного текста, проверяется распознавание,
затем самый быстрый вариант проверяется на числах и технической реплике.
Другие ядра могут изменить запись и её длительность; для сравнения нужно
учитывать и время полного синтеза, и его отношение к длине аудио.
Выбор варианта в отчёте скорости не означает, что его тембр принят на слух.

На этой Windows сборке `torch.backends.cuda.is_flash_attention_available()`
возвращает `False`. В исходной трассе присутствует SDPA math. Согласованное
повторение KV голов позволяет проверить другие ядра без сборки FlashAttention.
Ограничения GQA и различия результатов ядер описаны в
[документации PyTorch 2.9](https://docs.pytorch.org/docs/2.9/generated/torch.nn.functional.scaled_dot_product_attention.html).

### Результат оптимизаций: 6 октября 2026 года

Для короткой реплики после отдельного прогрева:

| Вариант | Синтез | Длина аудио | Синтез / аудио | Пик выделенной памяти |
| --- | ---: | ---: | ---: | ---: |
| Исходный, контроль в прогоне RMS | 11,67 с | 4,96 с | 2,353 | 2,68 ГиБ |
| Отключение скрытых состояний предсказателя | 11,72 с | 4,96 с | 2,363 | 2,68 ГиБ |
| Повторение KV голов | 9,72 с | 4,48 с | 2,169 | 5,14 ГиБ |
| Повторение KV + встроенная RMSNorm | 7,55 с | 4,88 с | 1,547 | 5,40 ГиБ |
| Только встроенная RMSNorm | 7,93 с | 4,56 с | 1,738 | 2,67 ГиБ |

Каждое время в таблице — медиана двух замеров своего прогона. Другие
вычисления изменили аудио, поэтому ускорение полного запроса нельзя
приписывать только скорости обработки одного отсчёта. Исходный контроль
во всех трёх прогонах побайтово совпадает с ранее принятой записью Base.
Отключение скрытых состояний также даёт тот же WAV; ускорения не получено.

Самый быстрый вариант заметно увеличивает выделенную память. Более
экономичный кандидат — **только RMSNorm**: техническая реплика 8,48 с
создана за 14,48 с, числовая 10,96 с — за 18,81 с. Все три его реплики
