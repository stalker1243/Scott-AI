# Эксперимент whisper.cpp

Отдельный C++17-процесс для сравнения распознавания с текущим Python Whisper.
Он читает сохранённый PCM float32, 16 кГц, mono, выдаёт NDJSON protocol 1 и
держит модель между запросами. Микрофон, воспроизведение и выполнение команд
отсутствуют. Эксперимент не включён в настройки или установщик ScottAI.

Исходники: [whisper.cpp v1.9.5](https://github.com/ggml-org/whisper.cpp/tree/v1.9.5),
commit `d1be6fde11ac6e0407606b4e42fe72d34add8037`, MIT. `json.hpp` из upstream —
nlohmann/json 3.11.2, MIT. Библиотеку не меняем. Исходники, SDK, веса, сборки и
замеры находятся в исключённом из Git `reports/whisper-cpp`.

## Сборка Windows

Нужны CMake 3.24+, Ninja и современный MinGW. На машине разработки GCC 13.1
из Qt не смог собрать Windows thread power throttling; GCC 16.1 UCRT собрал.
Компилятор Qt и основной лаунчер не меняются. Текущая CPU-сборка использует
AVX2/FMA/F16C; совместимость со старыми CPU ещё не проверена.

```powershell
./experiments/whisper_cpp/build.ps1
./experiments/whisper_cpp/build.ps1 -BuildName worker-vulkan -VulkanPrefix C:/ScottAI/reports/whisper-cpp/sdk/ucrt64
./experiments/whisper_cpp/build.ps1 -BuildName worker-cpu-blas -BlasPrefix C:/ScottAI/reports/whisper-cpp-pass2/blas-sdk/ucrt64
```

Для Vulkan нужны headers, loader import library, glslc и SPIRV-Headers CMake
config. SDK не входит в поставляемый распознаватель. При текущей сборке рядом
с EXE нужны `libgomp-1.dll` и `libwinpthread-1.dll` от того же MinGW; Vulkan
использует установленный драйвер. Их лицензии нужно сохранять при упаковке.

OpenBLAS — отдельный вариант сборки. `-BlasPrefix` указывает на подготовленный
MSYS2 UCRT prefix с `include/openblas/cblas.h` и `lib/libopenblas.dll.a`.
При сборке GGML использует эту библиотеку для больших матричных операций;
AVX2 CPU остаётся для остальных. В проверенном динамическом варианте нужны
также `libopenblas.dll`, `libgfortran-5.dll`, `libquadmath-0.dll` и
`libgcc_s_seh-1.dll`. В `reports/whisper-cpp-pass2` сохранены SHA256 официальных
пакетов и автономные сборки с лицензиями. Эта зависимость не устанавливается
в основной runtime ScottAI.

## Веса и сравнение

Официальный `models/convert-pt-to-ggml.py` преобразует копию существующего
checkpoint с assets того же установленного OpenAI Whisper. Исходник не
перезаписывается. В этой пробе используются F16-веса, без квантования.
GGML-файл немного больше исходного `.pt`; размер модели этим не уменьшается.

```powershell
py -3.13 experiments/whisper_cpp/benchmark.py prepare --corpus reports/whisper-cpp/corpus
py -3.13 experiments/whisper_cpp/benchmark.py run --corpus reports/whisper-cpp/corpus --output reports/whisper-cpp/trial --engine cpp --device vulkan --worker reports/whisper-cpp/worker-vulkan/ScottWhisperBench.exe --model reports/whisper-cpp/models/turbo/ggml-model.bin
```

`prepare` требует сохранённые синтетические WAV предыдущих проверок. Новый
отчёт создаётся в новой папке. Исходники backend копируются; testing_guard
блокирует пользовательские данные и ключи. Команды оцениваются по разбору,
а не выполняются. Контрольный корпус содержит 224 записи и 13 фоновых проверок.
Для Python передайте отдельную копию `.pt` внутри отчёта, `--engine python` и
`--device cpu` или `cuda`. `--ids` и `--repeats` задают замер одного набора.

Для сравнения декодера доступны `--prompt-space`, `--no-flash-attn` и
`--no-timestamps`. Они действуют только на C++ и записываются в `ready.decoder_options`.
Без флагов прежние параметры сохранены, старые экспериментальные бинарники
принимают прежний вызов. Не применять эти варианты к основному STT автоматически:
пробел поднял итог до 205/224, но потерял короткий «стоп» и разбор отрицания;
остальные два варианта дали 200/224 и 199/224. Проверка — `reports/whisper-cpp-pass2`.

Различия декодеров учитывать в выводах: beam 5, русский и подсказка одинаковы;
whisper.cpp при `--fallback 0.2` перебирает температуры до 1.0, Python — только
0 и 0.2. `--fallback 0` отключает перебор в C++. Узкий Python-повтор коротких
зациклившихся turbo-фраз ещё не перенесён. Средняя logprob текстовых токенов
C++ не равна `avg_logprob` Python. Время загрузки, первый вызов и дальнейшие
вызовы сохраняются отдельно. RSS C++ опрашивается каждые 20 мс; это нижняя
оценка пикового расхода памяти, а не VRAM. Новые отчёты Windows также сохраняют
пиковую working set, которую считает ОС. Синтетическая выборка не заменяет
проверку живого микрофона и эха.

Срок запроса задаётся `timeout_ms`. Encoder callback отбрасывает запрос до
вычислений, если время уже истекло. В v1.9.5 callback внутри тяжёлого encoder
может вернуться только после расчёта: владелец независимо ограничивает ожидание
сроком +250 мс, останавливает свой процесс и отбрасывает загруженную модель.
Проверяются PID и время создания. Новый процесс восстанавливает распознавание.
Реальный CPU-процесс прошёл 24 проверки: входы/границы/пути, таймаут, повтор,
активная остановка и повторный запуск. Готовность к подключению в production
требует отдельного потока отмены, ограниченного повторного декодирования,
проверки владельца при аварии backend и сохранения качества на отрицаниях/стопах.

Пути Windows теперь читаются из исходной UTF-16 командной строки и переводятся
в UTF-8. Модель загружается через поток `filesystem::path` и публичный
`whisper_model_loader`, без дополнительной копии весов в RAM. Этот прототип
использует CPU/Vulkan; автоматический путь OpenVINO здесь не поддерживается.
`check_unicode.py` проверяет модель, корень PCM, подсказку, имя PCM и их сочетание
с кириллицей, китайскими символами, emoji и пробелами. Он требует модель внутри
reports и создаёт только ссылки на неизменяемые экспериментальные веса.

```powershell
py -3.13 experiments/whisper_cpp/check_unicode.py --worker reports/whisper-cpp-pass2/bundle-cpu/ScottWhisperBench.exe --model reports/whisper-cpp/models/small/ggml-model.bin --corpus reports/whisper-cpp/corpus --output reports/whisper-cpp-pass2/unicode-trial
```

Linux CPU собран GCC 12 в Debian 12 Docker: семь WAV, запрет выхода за корень,
завершение по EOF. Dockerfile готовит только стенд. Это не пакет для Linux и
не проверка GUI/микрофона/Vulkan на Linux; время контейнера не сравниваем с
Windows как результат разных ОС.

Silero TTS всё ещё использует Torch. Перенос одного STT не убирает Torch из
приложения; CPU/TTS runtime и модели нужно учитывать отдельно. RX 580 и
физический AMD GPU этим стендом не проверяются.

## Владение процессом и отмена

Новый worker следит за настоящим родителем до загрузки модели. Windows
удерживает дескриптор процесса и сверяет время создания; Linux использует
pidfd, если он доступен, иначе проверяет родительскую связь в ядре. При
исчезновении владельца worker завершает себя, включая загрузку модели,
тяжёлое распознавание и ожидание ввода с удерживаемым каналом.

Для интеграции передавайте в необязательном JSON `owner_pid` вызывающего
процесса. Это должен быть настоящий родитель, иначе worker откажет до загрузки
модели. `benchmark.py --owner-watch` делает это автоматически и проверяет
`ready.owner_monitor`. Старый вызов из семи аргументов сохранён для сравнения
прежних бинарников. Явный PID нужен также для защиты от раннего завершения
родителя до начала worker на POSIX.

`Native.cancel()` можно вызвать из другого потока: он останавливает только
свой worker, отбрасывает поздний результат и запрещает повторное использование
этого контекста. Следующий запрос требует нового Native. Второй одновременный
запрос получает `busy`. Закрытие активного клиента тоже отменяет запрос;
обычное закрытие простаивающего клиента сохраняет выход по EOF. Ожидание,
остановка и получение статуса согласованы, чтобы избежать гонки с повторным
использованием Unix PID. Команда `cancel` через stdin в этом протоколе не
реализована: жёсткая отмена выполняется владельцем процесса.

Проверки: `check_lifetime.py` имитирует аварии отдельного тестового владельца,
`check_cancel.py` проверяет отмену, готовый поздний ответ, одновременную отмену
и закрытие, повторную загрузку и неверный PID. Только экспериментальные модели
и сохранённый PCM; микрофон, озвучка и исполнение команд отсутствуют.
Результаты Windows CPU/Vulkan и Linux CPU — `reports/whisper-owner`.

## Проверка качества поиска

Необязательный JSON worker принимает `beam_size`: целое 1–8, по умолчанию 5.
Готовность возвращает значение в `decoder_options`. Закреплённый upstream
ограничивает число декодеров восемью; patience там не реализован. Изменение
ширины поиска не воспроизводит алгоритм Python Whisper.

`benchmark.py --beam-size` выбирает ширину C++-поиска. В каждой строке отчёта
`native_result` сохраняет исходный текст, сегменты и время worker до фильтрации.
Это помогает увидеть выдуманный текст на фоне, даже когда он был отброшен.
Старые бинарники совместимы с обычным вызовом; новый параметр требует новой сборки.

`probe_short_retry.py` отдельно измеряет один повтор короткой петли с 300 мс
тишины по краям. Нужны полный C++ turbo-отчёт с native_result и те же worker,
модель и устройство. Скрипт создаёт свои PCM в новом reports, не меняет корпус
и ничего не включает в основном распознавании. Оценка текстовых токенов C++
не равна Python avg_logprob и не означает вероятность правильного ответа.

```powershell
py -3.13 experiments/whisper_cpp/probe_short_retry.py --worker reports/whisper-quality/bundle-vulkan/ScottWhisperBench.exe --model reports/whisper-cpp/models/turbo/ggml-model.bin --corpus reports/whisper-cpp/corpus --baseline reports/whisper-quality/beam-5/result.json --output reports/whisper-quality/retry-new --device vulkan
```

На полном корпусе поиск 1 дал 184/224, поиск 8 — 201/224 с потерей короткого
шумного стопа. При поиске 1 один фон сохранил текст после фильтрации.
Из 14 подходящих повторов политика не приняла ни одного нового текста;
все эти входы были намеренными повторениями. Настройки по умолчанию сохранены.
Разбор и результаты — `reports/whisper-quality`.

Полный CPU/OpenBLAS turbo: 201/224 решений, медиана 6,451 с. Запуск прерван
после 89 входов, оставшиеся 148 выполнены отдельно; код завершения первой
сессии неизвестен. Исключены первые вызовы обоих процессов. RAM около 2,08 ГиБ
по OS peak working set второго процесса; пика первой части нет. По сравнению
с Vulkan 5 улучшен ID 92, потерян ID 168. Фоны после фильтрации пустые, отрицания
24/24; перед фильтром 8 фонов содержат текст. CPU-повтор тех же 14 намеренных
повторений также не принял новых текстов. Основной STT остаётся прежним.

## Трасса финальных кандидатов

`instrument_source.py --output reports/<новый-каталог>` экспортирует закреплённый
upstream и добавляет hooks в отдельную копию. CMake принимает
`-DSCOTT_DECODER_TRACE=ON -DWHISPER_SOURCE=<копия>/source`. Оригинальный checkout
сохраняется. Потребуется новый каталог сборки: вложенный Vulkan shader-gen
сохраняет собственный SourceRoot в кеше.

Только диагностическая сборка поддерживает `benchmark.py --decoder-trace` и
JSON `trace_tokens=true`. Поле `decoder_trace` в ready/result сообщает протокол,
события, пределы и полноту. Записываются prompt, шаги, кандидаты до/после
ранжирования и байты токенов в hex. На запрос: 512 событий, 1 МиБ событий,
64 КиБ словаря; неполная запись отмечается явно. `ScottTraceChecks` проверяет
пределы, неверный JSON, сброс состояния, UTF-8 и NUL.

`trace_python.py` использует временные обёртки установленного декодера.
Берёт сохранённые решения VAD и сверяет подготовленный PCM; библиотека не
правится. Это не новый тест VAD/микрофона.

В reports/whisper-trace все 237 C++-результатов сохранены: 232 полные трассы и
5 gated-входов. Python — 32 прежних текста. В 10 из 12 парных ошибок правильная
команда есть среди кандидатов C++, но проигрывает оценке. Расчёт EOT на той же
пятёрке не изменил победителей. Отдельный режим `--renormalize-timestamps` или
JSON `renormalize_timestamps=true` исправил сумму вероятностей после масок,
но сохранил все 237 текстов. По умолчанию false, в приложение не включён.

Длинные сообщения передаются напрямую callback журнала: закреплённый formatter
повторно использует va_list для >1024 байт, что вызвало SIGSEGV на Linux.
После обхода Windows/Linux: протокол 34/34, отмена 67/67 при trace/beam 8,
recorder 8/8. ASAN полезного стека не дал и не считается успешной проверкой
памяти. Время трассировки не использовать как замер скорости обычного worker.

## Одинаковые спектрограммы и токены

`-DSCOTT_PREFIX_PROBE=ON` вместе с `SCOTT_DECODER_TRACE` собирает отдельный
`ScottPrefixProbe`. Нужна новая копия из текущего `instrument_source.py`:
в ней есть ограниченное копирование первого mel-окна. Оба флага default OFF.
Worker распознавания и production не используют этот инструмент.

`compare_prefix.py` берёт выбранные сохранённые входы и кандидатов прошлого
отчёта. Для turbo используется tokenizer с 100 языками. Python вычисляет окно
128×3000, округляет его к fp16 и сохраняет fp32: C++ получает те же значения.
Оба движка последовательно вычисляют raw logits на одинаковых prefix/целевых
токенах без beam search. C++ дополнительно проверяет собственный mel, Python —
fp16/fp32. Запись logits сохраняется в отдельных бинарных файлах; каждый последний
шаг сверяется с повторным расчётом полного префикса. Побитовая эквивалентность
пошагового и полного расчёта не предполагается.

```powershell
py -3.13 experiments/whisper_cpp/compare_prefix.py --output reports/whisper-prefix/new-trial --worker reports/whisper-prefix/bundle/ScottPrefixProbe.exe --ids 0 17 27 44 47 92 122 162 168 221
py -3.13 experiments/whisper_cpp/analyze_prefix.py --trial reports/whisper-prefix/new-trial
```

CLI probe: `model config.json cpu|gpu threads owner_pid`. Конфигурация protocol 1
ограничивает число входов до 32, планов до 8, prefix до 220, последовательность
до 96 токенов; входы лежат внутри каталога конфигурации. PCM до 60 с, mel ровно
80/128×3000, значения конечные. Выход — новый `cpp-output`, существующий каталог
не перезаписывается. Есть контроль настоящего владельца и срок в Python.
`check_prefix.py` проверяет реальные границы, пути, JSON, владелец/повтор и CPU-
расчёт на small с контролируемым mel; это не измерение качества распознавания.

Отчёт `reports/whisper-prefix`: 10 записей, по 76 replay на движок; 534 сравнения
шагов при одинаковом входе/токенах. Общие фильтры Python: fp16/C++ top1 525/534,
медиана TV 0,004092. Замена mel C++ — 533/534, fp16/fp32 Python — 533/534.
Оригинальные mel почти совпадают: максимальный RMSE 2,13e-7; округление fp16
заметно больше. C++ greedy token lookup отличается от Python BPE даже на одном
и том же тексте без начального пробела. Ни одно из этих измерений не доказывает
улучшение точности. Добавленный EOT и единые фильтры для принудительной
последовательности не воспроизводят фактическую остановку/ранжирование beam.
ID 47 использует первый Python-кандидат до штатного retry, а не конечный ответ.

## Точные токены подсказки в полном поиске

Диагностический `ScottWhisperBench` принимает JSON `prompt_token_ids`: 1–220
обычных целых ID 0…50256, без служебных токенов. Модель дополнительно проверяет
границу EOT. В этом режиме используются public `whisper_full_params.prompt_tokens`
и `prompt_n_tokens`; `initial_prompt` отключается. Одновременный `prompt_space`
запрещён, так как предоставленные ID уже полностью задают подсказку.
Обычная сборка без `SCOTT_DECODER_TRACE` отказывает этому параметру до модели.
При его отсутствии сохраняется прежнее распознавание, включая вызов с семью
аргументами. `ready.prompt_tokens` сообщает источник, ID и предел 220.

`benchmark.py --prompt-tokens reports/<файл>.json` читает ограниченный JSON-массив,
сохраняет SHA256 и проверяет принятие ID в ready. Относительный путь приводится
к абсолютному до перехода в изолированный backend. `check_prompt.py` проверяет
точность реально использованного prefix, предел 220, повтор и отказ plain;
`check_protocol.py` и `check_cancel.py` также принимают `--prompt-tokens`.

```powershell
py -3.13 experiments/whisper_cpp/benchmark.py run --corpus reports/whisper-cpp/corpus --worker reports/whisper-prompt/bundle-vulkan/ScottWhisperBench.exe --model reports/whisper-cpp/models/turbo/ggml-model.bin --device vulkan --output reports/whisper-prompt/new-exact --owner-watch --decoder-trace --prompt-tokens reports/whisper-prompt/python-exact.json
```

Полный эксперимент `reports/whisper-prompt`: четыре варианта × 237 входов.
Baseline сохранил 201/224. C++ с пробелом дал 205/224; Python BPE без пробела
202/224, с пробелом 203/224. Все три теряют прежнее решение отрицания ID 127,
варианты с пробелом теряют шумный стоп ID 47, BPE-варианты теряют команду «тише»
ID 186. После фильтра остаются 1/4/4 непустых фона. **Ни один вариант не принят**
для приложения. Подсказка Python в обоих BPE-прогонах точно совпала со входным
prefix на всех 232 декодированных входах. В парном Python-наборе из 32 записей
у exact-варианта осталось 10 ошибок; правильный кандидат есть в 8 из них.
Следующий разбор — выбор/завершение кандидатов; подмены грамматики не применять.

## Завершение кандидата и sampled EOT

Текущий `instrument_source.py` экспортирует дополнительную диагностику и два
необязательных эксперимента. Нужна новая source-копия: CMake проверяет наличие
нового API до сборки. Оригинальный upstream и прошлые отчёты сохраняются.

- JSON `finish_at_eot=true` / `benchmark.py --finish-at-eot` отключает завершение
  по метке конца аудио. Ограничения длины, deadline/abort и fallback остаются.
  При sampled EOT сохраняется последовательность до EOT для ранжирования.
- JSON `rank_eot=true` / `--rank-eot` добавляет logprob реально выбранного
  trailing EOT к score, если upstream исключает ровно этот один токен.
  Не добавляет придуманный EOT. Формулы avg_logprobs/entropy и пороги fallback
  сохраняются; другой победитель может изменить дальнейший fallback.
- Оба default false, только диагностическая сборка. Plain отказывает true
  до модели. Ready содержит `candidate_completion`. Без этих параметров
  прежний путь и семь аргументов сохраняются.
- Событие `termination` записывает причину входа в ветвь завершения — eot,
  audio_end или token_limit. Окончательное состояние видно в последующем
  `step/pre_rank/post_rank`; сам вход в ветвь не гарантирует успех кандидата.

`check_completion.py` на настоящем small проверяет ready, prefix, EOS,
формулу score/avg, повтор, границы recorder и отказ обычной сборки.
Существующие protocol/cancel проверки также принимают оба флага.

```powershell
py -3.13 experiments/whisper_cpp/benchmark.py run --corpus reports/whisper-cpp/corpus --worker reports/whisper-completion/bundle-vulkan/ScottWhisperBench.exe --model reports/whisper-cpp/models/turbo/ggml-model.bin --device vulkan --output reports/whisper-completion/new-both --owner-watch --decoder-trace --prompt-tokens reports/whisper-prompt/python-exact.json --finish-at-eot --rank-eot
```

Это частичная проверка механики Python-поиска. C++ по-прежнему держит завершённые
кандидаты в пяти decoder slots; Python хранит их отдельно и продолжает пять
активных последовательностей, используя topk(beam+1). Ожидание EOT и изменение
score не воспроизводят этот отдельный pool/поиск. Новые режимы не подключены
к основному распознаванию. Отчёт — `reports/whisper-completion`.

### Различные кандидаты на первом шаге

Наблюдение по сохранённым трассам: обычный C++ имеет один уникальный первый
токен в пяти slots на всех 232 входах, Python — пять на 30 входах парного
набора с шагами. C++ исключает повторения только начиная со второго шага.

`deduplicate_first_step=true` / `--deduplicate-first-step` — отдельный
диагностический режим, default false. При первом выборе проверяет ID против
всех уже выбранных первых токенов, сохраняя порядок существующих score/tie.
Если уникальных кандидатов меньше slots, лишний slot помечается failed;
бесконечного возврата к началу списка нет. Поздние шаги сохраняют upstream-
логику. Ready возвращает `deduplicate_first_step`. Plain отказывает true.

Первый вариант лишь включал существующее удаление соседних повторов на шаге 0.
Он дал 3–5 уникальных токенов, потому что одинаковые scores сортируются по
родителю, и повторы перемешиваются. Реальный тест поймал несоответствие.
В финальной копии проверяется весь набор выбранных ID. Предыдущие копии,
неуспешные тесты и полные результаты сохранены в reports; не считать их
проверкой окончательного механизма. `check_first_beam.py` проверяет настоящие
пять разных первых токенов, повтор, prefix, EOF и отказ plain.

### Настоящий выбор top-k

В закреплённом `whisper_sample_token_topk` вычисляется `partial_sort`, но ID
берётся из `discrete_distribution(decoder.rng)` с возвращением. Поэтому все
доступные кандидаты на первом шаге могут иметь один и тот же ID; удаление
повторов само по себе не гарантирует пяти разных вариантов.

`deterministic_topk=true` / `--deterministic-topk` выбирает `logits_id[i].second`
из уже отсортированного списка вместо случайного ID. Default false, только
диагностическая копия; ready отражает значение. Исходный sampler сохранён
при false. Сочетание с `deduplicate_first_step` даёт пять разных первых токенов
на проверенном fixture; `check_first_beam.py` проверяет этот режим.
Тесты промежуточной global-копии без top-k не прошли: у стохастического семплера
не хватило разных ID, slots получили failed, а тест ожидал пять. Ошибка теста
IndexError не была падением C++ и сохранена в отчёте.

Это всё ещё C++ beam: topk(5), отдельный finished pool и Python temperature-
fallback не перенесены. Полный корпус обязателен для оценки, одних пяти разных
токенов недостаточно. Новые режимы автоматически в приложение не включать.

## Отдельное хранение завершённых кандидатов

`finished_pool=true` / `--finished-pool` — следующий самостоятельный эксперимент,
default false, только диагностическая сборка. Нужен новый экспорт исходников
через `instrument_source.py`; CMake проверяет актуальный `scott_whisper_pool_limit`.
Обычный worker отказывает true до загрузки модели, false принимает.

При нулевой температуре этот режим:

- берёт sorted topk(beam+1) для каждого активного пути;
- удаляет повторы полных последовательностей на каждом шаге;
- сохраняет до beam завершённых по EOT кандидатов отдельно от активных;
- продолжает beam активных путей, пока хранилище не заполнится;
- при лимите дополняет хранилище активными префиксами без добавленной
  вероятности придуманного EOT;
- ранжирует по сумме вероятностей, включая действительно выбранный EOT,
  делённой на длину без EOT; avg использует длину+1.

`pool_select` сообщает число активных/завершённых путей; `pool_rank` — полные
кандидаты и победителя. Лимиты recorder сохраняются, неполная трасса помечается.
Пять разных первых токенов не означают правильного распознавания команды.

На положительной температуре остаётся прежний C++ fallback, включая beam
и entropy-фильтр. Python вместо beam использует best-of stochastic sampling
и compression ratio. Поэтому это ещё не воспроизведение всей логики Python.
Ready сообщает `zero_only`, ёмкость и `upstream_unchanged` для fallback/entropy.
Сочетание с прежними finish/rank/dedup/topk флагами отвергается, чтобы режимы
не накладывались друг на друга. `renormalize_timestamps` остаётся отдельным
необязательным экспериментом, в стандартную проверку pool не входит.

`check_pool.py` проверяет реальный small при beam 1/5/8, продолжение активного
поиска после EOT, пределы, prefix, ранжирование, повтор, EOF и plain refusal.
`check_protocol.py` и `check_cancel.py` принимают `--finished-pool`.

```powershell
py -3.13 experiments/whisper_cpp/benchmark.py run --corpus reports/whisper-cpp/corpus --worker reports/whisper-pool/bundle-vulkan/ScottWhisperBench.exe --model reports/whisper-cpp/models/turbo/ggml-model.bin --device vulkan --output reports/whisper-pool/new-exact --owner-watch --decoder-trace --prompt-tokens reports/whisper-prompt/python-exact.json --finished-pool
```

Сравнение полного корпуса и ограничения — `reports/whisper-pool`. Основное
распознавание, установщик и Qt этот инструмент не используют.

Финальная проверка: off 201/224 и все 237 прежних результатов; pool native
200/224 (2 исправления/3 потери), exact 203/224 (7/5), exact+renorm 203/224.
Exact теряет 20/47/77/127/186, отрицания 23/24; фоны после фильтра 2/1 у
exact/renorm. Все новые варианты отклонены. Четыре полных прогона, 948 входов,
928 полных трасс, по пять разных первых ID на 232 входах каждого pool-режима.
Windows/Linux: по 31 pool, 50 protocol, 67 cancel/reload, recorder 8;
230 защищённых сверок прошли. Положительная температура на корпусе не
вызывалась ни в одном из четырёх режимов. Следом сравнение полных оценок
правильных/выбранных последовательностей; отдельный temperature/fallback
контракт не считать гарантией исправления текущих ошибок.

### Принудительное завершение при лимите

JSON `pool_sample_limit` / `--pool-sample-limit` принимает целое 1–220 только
вместе с `finished_pool`. Необязательный параметр, стандартный предел остаётся
220; при выключенном pool сохранена исходная формула длины контекста.
Обычная сборка отказывает параметру до модели. Это диагностический предел,
в приложение и настройки пользователя он не подключён.

`pool_rank` дополнительно сохраняет `sampled_eot`, `eot_logprob`, `seek_delta`.
Для незавершённого префикса `sampled_eot=false`, добавленная вероятность равна
нулю. `check_finalization.py` на настоящем small проверяет лимиты 1/2/3/220,
сумму реально выбранных токенов/EOT, пределы, продвижение окна, повтор, EOF
и строгие типы аргумента. Это проверка механики, не качества коротких записей.

### Оценки полных последовательностей

`compare_scores.py` воспроизводит все пять финальных кандидатов выбранных
ошибок. Вход — сохранённые result.json/candidate-audit.json, output должен
быть новым каталогом reports. Использует прежний проверенный PrefixProbe,
одинаковые BPE IDs и общий mel. C++ также проверяется со своим mel, Python —
fp16/fp32. После raw logits на все режимы применяются те же официальные
Python-фильтры. Score учитывает timestamp и настоящий EOT, длина без prompt/EOT.

```powershell
py -3.13 experiments/whisper_cpp/compare_scores.py --output reports/whisper-scores/new-trial --worker reports/whisper-prefix/bundle/ScottPrefixProbe.exe --pool reports/whisper-pool/pool-exact/result.json --audit reports/whisper-pool/candidate-audit.json --ids 17 20 29 47 127 162 186
```

Сравнение не запускает новый beam и не воспроизводит побитово score живого
поиска: один принудительный путь отличается от пакетных активных beam,
фильтры/нормализация тоже могут отличаться. Полный Python checkpoint временно
копируется внутрь output и удаляется после проверки; исходный сохраняется.
Исходники, веса и корпус не меняются; команды и аудиоустройства не используются.
Отчёт — `reports/whisper-scores`.

Результат: 7 выбранных ошибок × 5 кандидатов, по 70 replay каждого движка.
C++ после общих фильтров выбирает правильный вариант в 0/7, Python fp16
в 3/7, fp32 в 4/7. Удаление EOT из суммы при прежней длине победителей не
меняет. Это пересчёт заданных путей, не улучшение точности и не доказательство
конкретной ошибки kernels/cache. Два полных контрольных GPU-прогона сохраняют
по 237 прежних результатов: off 201/224, exact pool 203/224.
Windows/Linux: по 58 finalization, 31 pool, 50 protocol, 67 cancel, recorder 8;
16 проверок сохранённых score и 230 защищённых сверок прошли. Следом влияние
кешированного/полного расчёта и Flash Attention на тех же последовательностях.

## Завершающая проверка кеша и Flash Attention

PrefixProbe принимает необязательные boolean `flash_attn` (default true) и
`full_replay` (default false) в config.json. Неверные типы отвергаются до
модели. При full_replay полный prefix пересчитывается отдельно для каждого
целевого токена после окончания кешированной последовательности; это не
меняет её KV-состояние между шагами. В rows сохраняются `full_logits` и
`incremental_full_all_steps_max_abs`; прежняя финальная сверка сохраняется.

`compare_attention.py --trial reports/whisper-scores/trial --worker <новый
ScottPrefixProbe> --output <новый reports-каталог>` сравнивает те же пять
финалов семи ошибок. C++ проверяется с Flash Attention/без него, common/native
mel и cached/full. Python full fp16/fp32 выполняется заново; cached Python
переиспользуется из явно указанного прошлого trial с SHA.

Итог reports/whisper-attention: полный расчёт не улучшил выбор правильных
решений. Без Flash Attention C++ выбирает правильный вариант в 3/7 (20/47/186),
но полный beam на 237 входах дал 203/224: исправил те же три записи и потерял
44/123/134 относительно прежнего exact pool. Отрицания 23/24, два непустых
фона. По сравнению с историческим Python 211/224 потеряны восемь верных решений,
новых исправлений нет. Вариант отклонён. Стандартный STT остаётся Python.

Default cached C++ raw logits всех 70 прошлых replay побитно сохранены.
Новые проверки probe Windows/Linux CPU — по 44, проверки данных — 13,
защищённые сверки — 230. Production/Qt/installer не менялись. Лабораторный
этап завершён с решением сохранить Python. По выбранной пользователем
очерёдности следующим идёт установка/размер, затем Linux, функции приложения
и последними настоящие устройства/микрофон.
