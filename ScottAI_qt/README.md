# Scott AI · Qt

Отдельный экспериментальный лаунчер на C++17 и Qt Quick/QML.
Десять разделов: Обзор, Диалог, Действия, Протоколы, Память, Модели, Система, Настройки, Внешний вид, Профиль.

Во «Памяти» доступны автоматические факты с отметкой «Из диалога»,
переключатель «Запоминать факты», число ответов в постоянной истории
и отдельная очистка диалогов. Факты и история сохраняются в backend:
[подробнее](../docs/memory.md).

В **Настройки → Голос** появился экспериментальный **Scott Voice**:
собственный мужской тембр, четыре варианта цифровой окраски, прослушивание
и статус подготовки. При сбое используется прежний голос. Кнопка
**Установить Scott Voice** готовит отдельный Python, библиотеки и модель.
Есть отмена, повтор и проверка готовности; текущий голос сохраняется.
Переключатель **Раннее начало речи** включает экспериментальную выдачу звука
во время синтеза. По умолчанию выключен, между блоками возможны паузы.
Для прежней отдельной установки доступно **Обновить Scott Voice**:
модель, библиотеки и настройки сохраняются.
**Ускоренный синтез** можно включить отдельно от раннего начала речи.
Режим сохраняется, при переключении текущая озвучка отменяется.
По умолчанию выключен; тембр сравнивается кнопкой «Прослушать».
Для раннего начала речи есть **Запас звука**: сразу, 2 секунды, 4 секунды
или вся фраза. Накопленные блоки воспроизводятся одним WAV. Больше запаса —
позже начало и меньше пауз; выбор сохраняется, по умолчанию «Сразу».
Последующие блоки используют тот же выходной поток звука до конца фразы;
отмена прерывает его. Ожидание генерации новых блоков ещё возможно.
Следующая часть раннего ответа готовится во время текущей озвучки;
в очереди подготовки допускается одна следующая часть.
**Подготовить к речи** заранее загружает модель и опору Scott Voice.
Состояние видно в настройках; подготовку можно отменить, готовую модель —
освободить. Через две минуты простоя работник освобождает память автоматически.
Это переносит загрузку до первого вопроса; сам синтез ещё требует времени.
[Настройка и проверки](../docs/development.md#scott-voice).

## Сборка и запуск на этой машине

Проверенный комплект: Qt 6.11.2 `mingw_64`, GCC 13.1.0 из
`C:/Qt/Tools/mingw1310_64`, CMake 4.4.3, Ninja 1.12.1.
Qt собран GCC 13.1.0. Скрипты ставят его перед GCC 16.1 из MSYS2 в PATH
только на время команды. Qt Creator и Qt Design Studio также установлены.

```powershell
powershell -ExecutionPolicy Bypass -File ScottAI_qt/build.ps1 -Test
powershell -ExecutionPolicy Bypass -File ScottAI_qt/run.ps1
# Сразу открыть память:
powershell -ExecutionPolicy Bypass -File ScottAI_qt/run.ps1 -Tab memory
# Сразу открыть настройки:
powershell -ExecutionPolicy Bypass -File ScottAI_qt/run.ps1 -Tab settings
# Сразу открыть профиль:
powershell -ExecutionPolicy Bypass -File ScottAI_qt/run.ps1 -Tab profile
# Сразу открыть действия:
powershell -ExecutionPolicy Bypass -File ScottAI_qt/run.ps1 -Tab actions
# Сразу открыть протоколы:
powershell -ExecutionPolicy Bypass -File ScottAI_qt/run.ps1 -Tab protocols
# Настроить модель и API Token:
powershell -ExecutionPolicy Bypass -File ScottAI_qt/run.ps1 -Tab models
# Посмотреть матовое стекло Glass:
powershell -ExecutionPolicy Bypass -File ScottAI_qt/run.ps1 -Style glass
```

Для других установок доступны параметры `-QtRoot`, `-CompilerRoot`,
`-Ninja` у сборки и `-Python` у запуска. В Qt Creator откройте
`CMakeLists.txt` и выберите комплект Desktop Qt 6.11.2 MinGW 64-bit.
В параметрах запуска задайте `--python <путь к python.exe>`.

## Что работает

- Асинхронные `/health`, `/metrics`, `/ask`, без блокировки окна.
- Диалог: несколько сохранённых чатов, поиск истории по названию, новый чат,
  переименование, очистка и удаление с подтверждением. Фото и документы можно
  выбирать или перетаскивать в окно; вложения остаются в черновике при ошибке.
  Отправка использует `/chats/{id}/messages` с настоящими байтами файлов.
  Значки возможностей выбранной модели показывают файлы, фото, видео и
  генерацию. «Картинка» создаёт изображение через OpenAI или OpenRouter,
  показывает результат и позволяет сохранить его. «Действие» выполняет
  команды Scott через прежний обработчик. [Форматы и ограничения](../docs/chat.md).
- История открывается боковой панелью с поиском и выделением текущего диалога.
  Модель и управление диалогом находятся в заголовке, вложения и режимы —
  рядом с полем сообщения.
- Недоступные файлы, фото и генерация объясняются после нажатия на функцию
  предупреждением с названием
  модели и переходом в её настройки. Неизвестная поддержка отмечается отдельно.
  Повторная проверка перед отправкой защищает вложения после смены модели.
- В голосовых настройках есть характер «Спокойный — мягкий и чёткий» для
  локальных голосов и рекомендация Евгения. Пробная фраза проверяет также
  частые ударения; [подробности и сравнение](../docs/voice.md).
- Распознавание микрофона и файлов использует общий Whisper, проверку тишины
  и ограниченное усиление тихой записи. [Модели и проверка точности](../docs/recognition.md).
- Модели: Groq, OpenAI, DeepSeek, Anthropic и OpenRouter. Выбор из каталога
  с поиском или ввод ID вручную. API Token скрыт; его можно временно показать.
  Смена провайдера очищает введённый токен, успех очищает поле; пустое поле
  использует уже настроенный ключ. Черновик остаётся при ошибке, обновлении
  каталога и переходе между вкладками. Активная модель показывается отдельно.
  Ключи каждого провайдера и выбор модели сохраняются локально в
  `backend/data/ai_config.json`, который исключён из Git. Проверка нового
  подключения сохраняет прежнее рабочее состояние до успеха и записи файла.
  Загрузка каталога и применение настроек выполняются в backend без блокировки
  запросов статуса и голоса. Форма поддерживает три стиля и окно 800×560.
- Действия: каталог `/abilities` с категориями, поиском по описаниям и фразам,
  фильтром доступных возможностей и причинами недоступности. Пример добавляется
  в черновик диалога; отправка выполняется кнопкой «Отправить» или Enter.
  Существующий черновик сохраняется, новая фраза добавляется с новой строки.
  При ошибке остаётся последний список, а кнопки примеров отключаются до
  успешного обновления. Загрузка каталога не выполняет команды.
- Протоколы: создание, редактирование, копии, поиск и фильтры. Шаг — любая
  команда словами, которую понимает Scott; доступны и вызовы других протоколов
  («протокол Имя»). Шаги можно переставлять, копировать, отключать, вставлять
  списком или добавлять из «Действий». Для каждого есть пауза до 60 с;
  весь сценарий повторяется от 1 до 20 раз. При ошибке можно остановиться
  или продолжить; итог сохраняет ошибки каждого шага. До 40 шагов в протоколе.
  Голосовые фразы и ежедневное расписание с выбором дней работают через
  общий backend. Расписание записывается словами: «пн, ср, пт в 18:00».
  Для первого сценария доступны шаблоны работы, фокуса и учёбы.
  Формат экспорта — JSON `scott-protocol` версии 1. Импорт открывает черновик
  с отключённым протоколом и очищенным расписанием. После проверки его можно
  сохранить и включить. Черновик сохраняется при ошибке и смене вкладки;
  сохранение показывает ответ сервера. Список, редактор и запуск разделены.
- Запуск протокола показывает текущий шаг и ответы выполненных шагов.
  «Остановить» прерывает дальнейшее выполнение; завершённые действия остаются.
  Определение сценария фиксируется на старте. При потере ответа на запрос
  запуска клиент проверяет состояние перед новым запуском. Удаление текущего
  выполняющегося протокола заблокировано. Состояние запуска доступно при
  скрытом окне; протокол продолжает работать в backend.
- Чат с выделением и копированием текста, Enter/Shift+Enter, состоянием ожидания
  и сообщениями об ошибках. Ответы не озвучиваются (`quiet_mode: true`).
- CPU, RAM, GPU и нагрузка на диск из backend каждые пять секунд.
- Тёмная/светлая темы, шесть акцентов, два новых значка приложения.
- Три стиля во «Внешнем виде»: **Classic**, **Glass**, **Terminal Pro**.
  Classic — привычное оформление; Glass — матовое окно с размытым фоном;
  Terminal Pro — зелёная палитра, сетка и моноширинный шрифт. Все поддерживают
  светлую/тёмную тему. Выбор сохраняется; акцент можно выбрать вручную или
  вернуть кнопкой «По стилю».
- Glass использует нативное размытие фона в Windows 10/11: Windows
  размывает рабочий стол и приложения позади окна. Во «Внешнем виде» есть
  «Матовость стекла» 0–100%, по умолчанию 40%. При 0% стекло ясное; выше
  включается размытие, а ползунок плавно увеличивает плотность цветной подложки.
  Радиус размытия задаёт Windows. Текст сохраняет полную непрозрачность, меню
  и диалоги имеют собственную подложку для чтения. На других системах меняется
  плотность подложки. Classic и Terminal Pro имеют сплошной фон. Прежний
  процент прозрачности используется как начальная матовость до первого сохранения.
  `run.ps1 -Style glass` задаёт стиль для просмотра при запуске; обычный запуск
  использует сохранённый выбор.
- Собственная строка заголовка: системное перетаскивание и изменение размера,
  сворачивание, разворачивание и восстановление. Двойной щелчок по заголовку
  разворачивает окно. Начальный размер — 920×660, минимальный — 800×560.
  Навигация занимает 64 px и раскрывается кнопкой ☰ до 164 px. Названия
  значков доступны в подсказках и при работе с клавиатуры. Обзор, Диалог,
  Действия, Протоколы, Память, Система и Профиль находятся сверху; Внешний вид и Настройки — внизу.
  Заголовок страницы находится в строке окна, карточки и подписи сокращены.
  При перетаскивании рамка подсвечивается; после отпускания в пределах 24 px
  от края рабочей области окно плавно занимает позицию с отступом 8 px.
  Во время системного перетаскивания координаты не анимируются.
- Разворачивание и возврат к обычному размеру плавно меняют границы окна за
  340 мс с мягким разгоном и остановкой. Кнопка в заголовке, двойной щелчок
  и системные команды Windows используют один переход;
  повторное нажатие разворачивает его с текущего размера. F11 включает
  настоящий полноэкранный режим, Esc возвращает прежний режим.
  Сворачивание сначала плавно скрывает окно за 260 мс; восстановление с панели
  задач или из трея плавно показывает его, сохраняя обычный, развёрнутый
  или полноэкранный режим. Отключение анимаций сразу завершает переход.
- Прозрачность панелей от 0 до 100% во «Внешнем виде». Значение сохраняется
  отдельно для каждого стиля; текст остаётся непрозрачным. «По стилю» возвращает
  исходную прозрачность. При 100% сквозь панели виден фон самого окна.
- Общие кнопки с откликом на нажатие и клавиатурный фокус, подсветка полей,
  поиск с очисткой, оформление списка категорий, полос прокрутки и уведомлений.
  Короткие вопросы на главной открывают черновик диалога.
- Переходы с уходом текущей страницы и появлением следующей, движущееся
  выделение меню и векторные значки. При быстрых кликах открывается последняя
  выбранная вкладка; отключение анимаций сразу завершает переход.
- Отклик кнопок и карточек на наведение,
  миниатюры тем, плавная смена цветов, переключатели настроек,
  заполнение индикаторов нагрузки и анимация ожидания ответа. Переключатель
  «Плавные анимации» находится во «Внешнем виде» и сохраняется отдельно.
  Циклические анимации останавливаются, когда окно скрыто.
- Всё окно плавно появляется за 360 мс и исчезает за 260 мс: при запуске,
  возврате из трея, закрытии крестиком и выходе через меню трея. Повторное
  открытие во время скрытия разворачивает переход с текущей прозрачности.
  Отключение «Плавных анимаций» сразу завершает переход. После появления
  непрозрачность окна возвращается к 100%; матовость Glass задаётся отдельно.
- Новые сообщения появляются отдельно: предыдущие элементы чата сохраняются.
  Если пользователь читает выше по истории, ответ не прокручивает её вниз;
  отправка собственного сообщения возвращает к концу диалога.
- Память: категории из backend, поиск, добавление до 200 символов и удаление
  отдельной записи после подтверждения. Используются те же `/memories`, что
  в Avalonia и голосовых командах. Массовое удаление пока не переносилось.
  При ошибке добавления черновик сохраняется; повторное нажатие блокируется.
- Профиль: имя до 60 символов, «о себе» до 300, характер ответов из списка
  Scott и до 12 интересов по 40 символов. `/personality` использует общие
  сведения для Qt, Avalonia и ответов ассистента. Сохранение подтверждается
  ответом сервера; ошибки, обновление данных и переходы сохраняют черновик.
  Фото выбирается через системный диалог; кадр сдвигается мышью, приближение
  1–4× меняется ползунком или Ctrl+колесом. Фото с кадром сохраняются локально
  в каталоге данных Qt одним атомарным файлом `profile/avatar.json`.
  При первом открытии используется фото из `%APPDATA%/ScottAI`, если оно есть.
  Удаление фото и отмена черновика доступны на странице. Фото можно сохранить
  без подключения, если поля профиля не менялись. Во время запроса редактирование
  заблокировано; после ошибки записи фото остаётся в черновике.
- Трей: открыть/скрыть окно, Диалог, Настройки, тихий режим, пауза голосового
  ассистента, закрепление поверх окон, центрирование, запуск/остановка Scott
  и выход. Остановка backend доступна только для процесса этого лаунчера.
  Пауза вызывает `/listen/stop`, возобновление — `/listen/start`; состояние
  проверяется через `/listen/status`. Текстовый диалог продолжает работать.
  При недоступном микрофоне и во время переключения команда заблокирована.
  Ошибка переключения возвращает фактическое состояние; меню не включает
  микрофон автоматически. Тихий режим управляет озвучкой через `/audio/quiet`.
  Новые ответы при скрытом/свёрнутом окне вызывают уведомление без текста
  ответа; щелчок открывает Диалог. Уведомления отключаются в меню трея или
  в Настройки → Прочее. Подсказка значка показывает состояние, CPU/RAM и микрофон.
  Скрытие/возврат используют общую анимацию окна; настройки навигации, закрепления и
  уведомлений сохраняются. Закрытие в трей включается отдельно.
- Настройки: тихий режим, громкость, микрофон и динамики, голос с пробной фразой,
  характер речи и отдельный выбор Авто/NVIDIA/AMD/Процессор для Whisper и Silero,
  а также Apple для Silero. Учитываются доступность CUDA, ROCm/HIP, Metal
  и ограничения переменных окружения. AMD требует совместимой карты, драйвера
  и PyTorch: [инструкция](../docs/amd-support.md). Подпись «Выбрано» показывает
  устройство для загрузки; после сбоя GPU модель может продолжить на CPU.
  Громкость сохраняется кнопкой «Применить». Загрузка данных не отправляет
  изменений; во время записи повторные действия блокируются. Выбранный голос
  и остальные параметры сохраняются в backend после перезапуска. Доступны
  все локальные и облачные голоса из каталога, включая Светлану.
  В «Прочем» доступны настройка трея, сброс оформления с подтверждением и
  просмотр версий команд. Сброс оформления меняет только параметры Qt.
- Разделы настроек переключаются через общую движущуюся подложку и плавное
  появление содержимого. Каждый раздел запоминает свою позицию прокрутки;
  черновик громкости сохраняется при переключениях. Раздел можно выбрать
  клавишами ←/→, Home/End. Во время запроса виден индикатор работы Scott.
  Списки отмечают выбранный пункт, переключатели и ползунки реагируют на
  наведение. Все эффекты учитывают настройку «Плавные анимации».
- Подключение к существующему backend и запуск по кнопке, когда его нет.
  `run.ps1` также запускает его автоматически через `--start-backend`.
  Останавливается только свой процесс. Оба потока Python вычитываются,
  `SCOTT_PARENT_PID` позволяет backend завершиться при аварии лаунчера.

Оформление и поведение окна хранятся отдельно: QSettings `ScottAI/QtPrototype`
(на Windows — HKCU/Software/ScottAI/QtPrototype). Голос, звук и устройства
используют общие настройки backend, как в Avalonia.
Диалоги и вложения сохраняются в `backend/data/chats`. Прежняя переписка
однократно появляется в истории отдельным диалогом. Очистка и удаление
убирают связанные записи из памяти разговоров; отдельно сохранённые факты
остаются во вкладке «Память».

## Границы эксперимента

Для разработки нужны Qt и рабочий backend с Python 3.13. Установщик Qt
содержит необходимые библиотеки Qt и встроенный Python. Первый запуск
подготавливает зависимости и модели речи с прогрессом, отменой и повторной
попыткой. Сборка: `python installer/build.py --installer`; вариант Avalonia:
`python installer/build.py --launcher avalonia --installer`.
Обновления и оставшиеся разделы исходного лаунчера ещё предстоит перенести.
Код/Markdown в ответе показан текстом.
Сравнительных выводов о производительности по этому прототипу пока нет.
Состояние разделов и порядок дальнейшего переноса — в [MIGRATION.md](MIGRATION.md).

## Проверки

`chat_contract`: отдельный HTTP-сервер проверяет историю, переименование,
очистку, multipart с содержимым и Unicode-именами файлов, защиту от повторной
отправки и сохранение вложений при ошибке. `chat_screens` (`--smoke-chat`)
проверяет три стиля, историю, подтверждения, вложения и результат генерации
на вымышленных данных в окне 800×560.

`setup_contract`: тестовый процесс проверяет обнаружение первого запуска,
прогресс, ошибку, повторную попытку и отмену. `setup_screens` (`--smoke-setup`)
проверяет экран подготовки на вымышленных данных. Эти проверки не скачивают
библиотеки и не отправляют запросы к платным моделям.

`client_contract`: локальный HTTP-сервер проверяет настоящий C++ клиент:
структуру запроса, quiet_mode, защиту от двойной отправки, разбор ответа,
восстановление после некорректного JSON и отключения backend.
Проверяются и операции памяти: категория и текст, повторы, ошибки записи и
удаления, сохранение списка при неудачной загрузке. Настоящие данные не меняются.
Для настроек проверяются загрузка без записи, форматы запросов, повторные
нажатия, ограничения CPU/GPU, ошибки сохранения, недоступные разделы после
неудачного чтения и восстановление. Пробная речь проверяется на тестовом сервере.

`tray_contract`: проверяет переходы в Диалог/Настройки, локальные настройки,
блокировку недоступных команд, паузу/возобновление микрофона, тихий режим и
восстановление после ошибки на отдельном HTTP-сервере. Проверяет уведомления
только для ответов в фоне, отключение уведомлений и очистку чата. Настоящий
микрофон, backend и системные уведомления в этом тесте не используются.

`profile_contract`: проверяет чтение/запись `/personality`, лимиты, повторные
нажатия, подтверждение сервера и ошибки. Отдельно проверяет кадрирование,
атомарное сохранение/загрузку фото, отмену, удаление и повреждённые файлы.
Использует отдельный HTTP-сервер и временные изображения. `--smoke-profile`
запускает только визуальную проверку профиля за несколько секунд: черновик,
кадр, загрузка/ошибка, подтверждение сохранения и ограничение длины. Снимки
включают нижнюю часть формы с интересами и сохраняются в `build/screenshots`.

`actions_contract`: проверяет `/abilities` на отдельном HTTP-сервере: доступные
и недоступные действия, счётчики, защиту от двойной загрузки, ошибки и
некорректные ответы, отключение и восстановление подключения, пустой каталог.
Проверяет, что чтение каталога не отправляет команды.
`--smoke-actions` проверяет только новую страницу: поиск, категории,
доступность, черновик диалога, три стиля и окно 800×560. Использует
вымышленные данные, снимки сохраняет в `build/screenshots`.

`protocol_contract`: отдельный HTTP-сервер проверяет загрузку, PATCH по id,
подтверждение сохранения, ошибки, защиту от повторов, запуск/остановку,
восстановление после потери ответа и перезапуска backend, удаление.
Импорт/экспорт проверяются на временных файлах, настоящие команды не исполняются.
`protocol_screens` (`--smoke-protocols`) проверяет редактор, копирование шагов,
вставку списка, выбор из действий, черновик при ошибке, подтверждение записи,
импорт, удаление, остановку, выбор шаблона щелчком и подтверждение замены
черновика на вымышленных данных. Снимки трёх стилей при
800×560 — `build/screenshots/page-100.png` и последующие.

`qml_screens`: открывает восемь страниц на вымышленных данных из
`tests/PreviewData.qml`, проверяет обе темы, отключение анимаций, быстрые
переключения, окно 800×560, подтверждение удаления и поиск в памяти.
Также проверяет добавление/очистку сообщений без пересоздания предыдущих,
отключение анимаций посреди перехода, повторный выбор во время ухода и
появления страницы, скрытие и восстановление окна.
Снимки также покрывают новые стили, фокус поля, раскрытый список категорий,
уведомления об ошибке/успехе и смену стиля при отключённых анимациях.
Также покрываются три раздела настроек, маленькое окно в Terminal Pro,
прозрачность 0/100% и изменение её ползунком.
Проверяются быстрые переключения разделов настроек, сохранение прокрутки и
черновика, отключение анимаций посреди перехода и скрытие окна. Снимки включают
светлую тему, раскрытый список устройств, загрузку, ошибку и диалог сброса.
Проверяются раскрытие/сворачивание навигации, закрепление поверх окон,
притягивание к краю рабочей области, скрытие/возврат с анимациями и без,
сворачивание/разворачивание собственного заголовка,
alpha-канал Glass и матовость 0/40/100%. Для проверки композиции Windows
используется небольшая поверхность Qt с тем же WindowEffects и отдельное
окно позади неё: изменение его цвета должно менять видимый фон ясного стекла.
Контраст полос на этом окне должен снизиться при включении размытия сильнее,
чем при обычном смешивании alpha. Проверяются
восстановление эффекта и его отключение при смене стиля. Снимки
`glass-clear.png`, `glass-frosted-*.png` и `glass-desktop-*.png` содержат только
область тестовой поверхности, заполненную этими двумя собственными окнами.
Проверка порядка окон и непрозрачного текста отменяет снимок при перекрытии.
`--smoke-glass` запускает только эти проверки (около 10 секунд).
Проверка композиции требует интерактивного сеанса Windows: изолированный
сеанс сборки может возвращать чёрный кадр QScreen при исправной отрисовке Qt.
Проверяет завершение переходов и ошибки QML, сохраняет снимки настоящей
Qt-сцены в `build/screenshots`. Не обращается к backend и не записывает настройки.

`window_lifecycle` (`--smoke-window`) проверяет первый показ, плавное изменение
непрозрачности всего окна, прерывание скрытия открытием, повторные нажатия,
закрытие в трей и обычное закрытие, отключение анимаций во время перехода,
восстановление Glass и завершение выхода из трея после исчезновения окна.
Использует вымышленные данные и временные настройки.
Также сравнивает фактическую композицию Windows при прозрачности окна 100%,
40% и 5% в трёх стилях. Под тестовым окном находится собственная поверхность;
проверка отменяет захват, если эти два окна перекрыты другим приложением.

`window_states` (`--smoke-states`) проверяет кнопку разворачивания, промежуточные
размеры реального окна Windows, восстановление исходной позиции и размера,
быстрый повторный выбор, F11/Esc, сворачивание и восстановление из трея,
системные команды Windows (включая повторное разворачивание и восстановление
из свёрнутого полноэкранного режима), отключение анимаций и сохранение Glass.
Использует вымышленные данные, нажатия направляет только своему окну.
Снимок полноэкранной Qt-сцены —
`build/screenshots/window-fullscreen.png`.

`models_contract` проверяет `/ai/providers` и `/ai/configure` на локальном
тестовом сервере: свой ID модели, передачу и повторное использование токена,
защиту от двойного применения, ошибки, подтверждение фактической модели и
переподключение. `models_screens` (`--smoke-models`) использует вымышленные
провайдеры и токены, проверяет поиск, маскировку, очистку и сохранение черновиков,
ручную модель, доступность кнопок, три стиля и компактный размер. Снимки —
`build/screenshots/models-*.png`. Настоящие ключи эти проверки не читают.

`--check-backend` — отдельная ручная проверка с настоящим backend: отправляет
вопрос «Сколько свободной памяти?», проверяет ответ и метрики и сохраняет
`screenshots/live-chat.png`. Этот вопрос попадёт в обычную историю backend.
Можно сочетать с `--start-backend --python <путь>` для проверки запуска.
Диагностика Qt пишется в `qt-launcher.log` в рабочем каталоге.

## Добавление стилей

Каталог — `StyleCatalog.js`. Новая запись содержит стабильный `id`, название,
описание, шрифт, радиусы, тип декора (`none`, `glass`, `terminal`) и две палитры:
`dark`/`light` с полями `bg`, `sidebar`, `surface`, `elevated`, `ink`, `muted`,
`line`, `popup`, `accent`. Карточка выбора добавится автоматически.
Для нового типа фонового декора нужно также дополнить `StyleBackdrop.qml`.
Палитра/геометрия общих панелей задаётся через `SurfacePanel.qml` и `visual`
в Main.qml. В QSettings хранится строковый `styleId`, поэтому порядок каталога
можно менять. Неизвестный ID при загрузке заменяется Classic. Старые значения
`surfaceStyle` 0/1/2 читаются как Classic/Glass/Terminal Pro.

Проект использует стандартный [модуль QML в CMake](https://doc.qt.io/qt-6/qt-add-qml-module.html).
Матовое стекло использует динамически доступную accent policy через
[SetWindowCompositionAttribute](https://learn.microsoft.com/en-us/windows/win32/dwm/setwindowcompositionattribute).
Это путь совместимости для поверхности Qt; при его отсутствии применяется
[DWM Desktop Acrylic](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type)
в Windows 11 22H2 и новее. У accent policy нет гарантии стабильности Windows;
эффект изолирован в WindowEffects, а ошибка API оставляет цветную подложку.
Анимации свойств задаются через [Qt Quick Behavior](https://doc.qt.io/qt-6/qml-qtquick-behavior.html).
Общие элементы основаны на [настройке Qt Quick Controls](https://doc.qt.io/qt-6/qtquickcontrols-customize.html).
